# Prompt: report-bug

Job prompt: принять наблюдение бага, комментарий с ревью или сырой лог/дамп ошибки, уточнить неоднозначности у человека, сопоставить со спецификацией и оформить атомарный файл задачи в `docs/todo/<story>/bug/NN-<slug>.md`.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем сырой текст наблюдения / комментария ревью или путь к файлу входящего дампа (например, `docs/todo/inbox/comment.txt`).

В GUI агентов: вызов скилла `/report-bug`.

---

## 0. Preconditions

- `stage: spec-first`.
- Роль: **Auditor / Bug Triage**. Не пишет продуктовый код и не правит тесты.
- Вход: сырое текстовое описание из чата ИЛИ путь к файлу входящих данных (`docs/todo/inbox/**`, лог, текст ревью).
- За один вызов триажится **одно** логическое замечание/дефект. Пачка замечаний — последовательный триаж или нарезка по одному.

## 1. Input & Intake

1. Прочитай входящее наблюдение (из текста вызова или указанного файла).
2. Найди затронутый bounded context и соответствующие модули в `docs/spec/**`.
3. Если во входящем описании недостаточно информации для однозначного воспроизведения или понимания проблемы:
   - **Stop-and-Ask**: задай человеку конкретные уточняющие вопросы (шаги воспроизведения, ожидаемое поведение, граничные случаи).
   - Не додумывай поведение за человека и не угадывай скрытый бизнес-контекст.

## 2. Classify vs Specification

Сопоставь фактическое поведение (`Observed`) с требованиями действующей спецификации (`docs/spec/**`):

| Ситуация | Классификация | Действие в триаже |
|---|---|---|
| Спека требует правильного, код расходится | `trivial` | `Spec delta: none`. Фиксируется баг реализации. |
| Спека молчит или ошибочна, исправление однозначно | `spec-patch` | `Spec delta: docs/spec/0X-module.md#anchor`. Описывается дельта спеки. |
| Требуется выбор архитектурного пути / дизайна | `adr+spec` | Создаётся черновик `docs/decisions/NNNN-<slug>.md` (`accepted: false`). |
| Поведение уже прямо закреплено в спеке (или объявлено out-of-scope) | **Не баг** | Стоп. Объясни человеку, почему поведение соответствует спеке, файл не создавай. |

## 3. Create Bug File

1. Определи целевую историю `<story>`:
   - Если дефект относится к существующей истории в `docs/todo/<story>/`, используй её.
   - Если история не указана или относится к общим дефектам подсистемы, используй `docs/todo/maintenance/` (создай README истории, если его нет).
2. Вычисли следующий номер `NN`:
   - `NN = 1 + max(Closed ∪ live task/bug files)` по таблице в `docs/todo/README.md`.
3. Сформируй файл `docs/todo/<story>/bug/NN-<slug>.md` по контракту:

```markdown
# Bug NN: <Short Title>

- **kind**: bug
- **opened**: YYYY-MM-DD
- **branch**: bugfix/<slug>
- **Spec delta**: docs/spec/0X-module.md#anchor <!-- или none, если спека не меняется -->

## Observed vs Expected
- **Review / Report**: <краткая цитата или суть исходного комментария>
- **Observed**: <что происходит фактически / симптомы ошибки>
- **Expected**: <что требует спецификация docs/spec/ со ссылкой на якорь>

## Definition of Done
- [ ] Fix: <что именно должно быть исправлено в коде>
- [ ] Regression test: <название конкретного теста, воспроизводящего ошибку>

## Run
<команда запуска или курл для проверки без секретов и кредов>
```

4. Зарегистрируй баг:
   - Добавь строку в таблицу `## Bugs` в `docs/todo/<story>/README.md`.
   - Убедись, что история числится в `docs/todo/README.md` (`## Open Stories`).
5. Если баг создавался из файла в `docs/todo/inbox/`, перемести файл в `docs/archive/inbox/` или удали его.

## 4. Definition of Done

- [ ] Неоднозначности уточнены у человека; не-баг аргументированно отклонён без создания файла
- [ ] Поведение сопоставлено со спецификацией `docs/spec/**`, определена `Spec delta`
- [ ] Вычислен уникальный сквозной номер `NN`
- [ ] Создан файл `docs/todo/<story>/bug/NN-<slug>.md` строго по контракту
- [ ] Баг зарегистрирован в README истории и в `docs/todo/README.md`
- [ ] Продуктовый код и тесты **не тронуты** (zero code diff)
- [ ] Коммит оформления задачи выполнен локально: `git add docs/todo/ && git commit -m "docs(todo): register bug NN <slug>"`

В конце ответа по-русски: путь к созданному файлу бага, ссылка на якорь спеки, следующая команда для выполнения (`/fix-bug docs/todo/...`).
