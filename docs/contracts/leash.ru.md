# Конверт записи (DeltaFuse ↔ leash / хост)

[English](leash.md) | [**Русский**](leash.ru.md)

Машинная схема: [leash.schema.yaml](leash.schema.yaml) (контракт v1).

**Канон продюсера.** `deltafuse leash`, hook или хост пинят ту же схему. Не схема продукта; installer не копирует `docs/contracts/**`.

Продюсер: `deltafuse next --json`. Проверка: `deltafuse leash`. `envelope` — объект по схеме или JSON `null`. `null` — нет готового шага воркера. Любой путь в diff, который не исключён и не покрыт envelope, — orphan, `leash` падает (и при пустом envelope, и при открытом). `docs/spec/**` — orphan только после `project.baseline: accepted`.

**Что судится и что исключено.** Судится каждый путь, а не только `src/**`, `tests/**` и ops/deploy: `pom.xml`, `conftest.py`, `README.md`, `CHANGELOG.md`, `.gitignore`, workflow CI — файлы продукта. Change пишет файл вне корней по умолчанию, только если человек назвал его в `workflow.code_roots` (глоб или файл, например `pom.xml`), а задача — в `allowed_paths`; иначе его коммитит человек (`git commit --no-verify`), а диапазон всё равно судит CI. Исключены только: `.deltafuse/**` (у журналов, lock и config свои проверки), `docs/intake/**`, `AGENTS.md`, `docs/archive/**` (архив закрытых Change и источники intake, которые туда переносит Intake), `docs/spec/**` при `project.baseline: draft` и кэши интерпретатора там, где кэш действительно лежит. `README.md` по имени и `CHANGELOG.md` больше не исключены.

**Пути.** Одна нормальная форма: относительно корня продукта, `/`, без сегментов `.`, `..` и пустых, без диска. `--file` разрешает то, что набрано (абсолютный путь внутри продукта, `..`), и отказывает пути, выходящему из продукта. `allowed_paths` и `forbidden_paths` задачи уже должны быть в этой форме: гейт `decomposed` и Writer отказывают всему остальному.

**Границы Change.** Envelope называет каталог своего Change (`docs/changes/<dir>/...`), а не `docs/changes/*/`. В этих глобах `*` — один сегмент пути, `**` — любая глубина. Change, сошедшийся к базе и не переоткрытый после неё, не открывает envelope; файл Change, не покрытый ни одним envelope, — нарушение независимо от того, готов ли другой шаг.

**Задачи.** Задача открывает envelope Declare/Implement только такой, какой её оставил Decompose: её файл должен быть в коммите, записавшем последнюю квитанцию `decomposed` этого Change, а `allowed_paths` не шире, чем в нём. Пока эта квитанция не закоммичена, leash датировать задачу не может; Writer отказывает новой задаче и новым `allowed_paths`/`forbidden_paths` любой задачи, как только по квитанциям Decompose закрыт.

**Архив Change.** `deltafuse archive` переносит Change в `docs/archive/changes/`. Change, заархивированный в судимом diff, учитывается как активный: его квитанции и задачи из архива дают те же envelope. Отсутствующий файл Change — перенос, а не удаление, если этот Change заархивирован в судимом дереве и файл есть в архиве.

**Раскладка репозитория.** Корень продукта — корень его git-репозитория (или git нет). В подкаталоге репозитория `deltafuse init` и `deltafuse leash` отказывают, `advance` пишет `checked: false` с причиной. Монорепозиторий — пункт roadmap.

**Закреплённое ядро.** Hook и `deltafuse leash` (в любом режиме) отказывают с кодом `2`, если работающее ядро — не то, что закреплено в `.deltafuse/lock.yaml`, или config требует другой framework, чем lock: diff не судится по правилам другого ядра.

**Откаты.** Квитанция, возвращающая Change назад, — граница шага, как гейт: переоткрытый gap (назад в Analyze), отклонение принятой спецификации (`gap-reopen` с gap `spec-rejected`, назад в `analyzed`), переоткрытие задачи после гейта `implemented` (`artifact-status` самого Change с причиной `task reopened`, назад в `declared`). Цепочка продолжается с шага после неё, а `advance` судит шаг от коммита перед тем, который её записал.

**Первый коммит.** Hook пропускает коммит без родителя и коммит (диапазон), в базе которого нет `.deltafuse/lock.yaml` (установка DeltaFuse): его не с чем сравнить. Каждый следующий коммит судится.

**Нет hook.** Hook не клонируется, а `core.hooksPath`, заданный после `init`, уводит git от установленного hook. `deltafuse leash` (`warnings` в JSON и stderr в обоих режимах), `deltafuse next` (`warnings` в снимке `--json`, stderr при `--human`) и `validate-layout` (stderr, не ошибка) сообщают, что leash включён, а hook его не запускает; ставит его `deltafuse init`. В CI (задана `CI`) не сообщают. Если diff не судится вовсе (первый коммит, база без DeltaFuse), в ответе есть `note`, а текстовый режим печатает `leash: not judged: <note>`.

**Файлы под `.gitignore`.** Неотслеживаемые файлы, которые git игнорирует, судятся, если лежат в корне кода, а сам `.gitignore` судится как любой файл — правило игнорирования ничего не прячет. Каталог, игнорируемый целиком (`target/`, `node_modules/`), — вывод сборки и не перечисляется. Неигнорируемый вывод сборки — orphan: человек добавляет его в `.gitignore`.

Intake `write` не содержит `src/**`. Declare/Implement оставляют evidence и `tests/**`, код сужается до `allowed_paths`. При `workflow.code_roots` тестовая сторона — каждый корень, чьи собственные каталоги тестовые (`svc/tests/**`, `app/src/test/**`); корень, где код и тесты вместе (`src/**` модуля Maven), открывает только `allowed_paths` задачи, включая тест. Корнем кода может быть один файл (`pom.xml`). Свежий `init` пишет `workflow.leash: advisory`. Отсутствующий ключ или значение, не являющееся режимом, — `enforce` для всех (leash, проверка hook, `advance`, установщики). `off` — без hook, `advance` не проверяет. `advisory` — те же нарушения, exit 0; `deltafuse advance` сам запускает ту же проверку до записи квитанции и сообщает нарушения, не отказывая. `enforce` — `advance` отказывает в переходе, пока путь вне envelope. Продукт без git или без коммита проверить нельзя: `advance` пишет `checked: false` с причиной и не блокирует. `enforce`/`advisory` ставят локальный `pre-commit` на `deltafuse leash` в каталог hook самого git (`core.hooksPath`, если он указывает внутрь репозитория или его git-каталога; для общего каталога hook вне репозитория — сообщение, как вызвать `.deltafuse/hooks/pre-commit`). Hook не делает `git push`.

**Режим и корни вердикта.** Diff судится режимом и корнями кода из `.deltafuse/config.yaml` базы; более строгий режим в судимом или рабочем дереве действует сразу. Коммит, ослабляющий `workflow.leash` или меняющий `workflow.code_roots`, сам вне любого envelope: это настройки человека, их коммитят отдельно. Внутри шага `advance` держит режим, с которым шаг начался.

При `halt.kind` `decision` или `spec` `envelope` — JSON `null`: product-code write-tools выключены, пока висят кнопки.

**По чему судится diff.** Guard сверяет diff от `--base` (по умолчанию `HEAD`) с готовыми envelope **и** с envelope всех шагов, которые каждый Change прошёл с этой базы, — по receipts переходов. Записи законченного шага не судятся по envelope следующего; halt останавливает новую работу, но не запись уже сделанной. Для Declare/Implement добавляются только задачи, чей файл изменился с базы, и только по записи, которую `deltafuse evidence` проштамповал для этого Change, задачи и фазы; `allowed_paths` объявленной задачи читаются из задачи в том виде, в каком она объявлена на базе.

**Что судится.** Hook `pre-commit` судит индекс (индекс против `HEAD`, байты из индекса). `deltafuse leash` судит рабочее дерево. `advance` судит весь шаг: каждый не-merge коммит первой линии с коммита, с которого шаг начался (родитель коммита, записавшего последний receipt перехода Change), и незакоммиченный diff, так что `git commit --no-verify` запись не прячет. `--base B --head H` (CI) судит `B...H`, от merge base. Пути читаются сырыми (не-ASCII имена) и без поиска переименований (перенос показывает удаление).

**Журналы ядра (DF3-007).** `.deltafuse/transitions.jsonl`, `gate-journal.jsonl` и `journal-head` проходят только как дописывание в форме ядра: старые строки не тронуты, digest каждого receipt перехода сходится и цепочка воспроизводится, gate-receipts текущего формата с проверенными цепочкой и head. Иначе — нарушение. `.deltafuse/gate-password.yaml` (хэш пароля Human Gate) в diff воркера не бывает никогда. `.deltafuse/bench.yaml` охраняется так же: там лежат `seed_hashes`, по которым bench-прогон оценивает `code.untouched`, поэтому файл пишет только гарнитура, инициировавшая продукт, — воркер, переписавший эти дайджесты, стёр бы собственные преждевременные правки `src/**`. Digest receipt без ключа: guard доказывает форму записи ядра, а не авторство — это п. 4 роадмапа. То же для receipts Artifact Writer в `.deltafuse/receipts/`: самодельный receipt может подтвердить рукописный структурный артефакт. Чистый `git merge` не запускает `pre-commit`, поэтому принесённое слиянием судит CI-задача leash, а не локальный hook. См. [Чего ядро не останавливает](../core-and-worker.ru.md#чего-ядро-не-останавливает).

**Записи статуса ядром.** Файл задачи или слайса вне envelope проходит только как перезапись, которую делает `deltafuse state`: с базы дописан receipt `artifact-status`, статус сменился с `from` первого receipt на `to` последнего, остальной frontmatter и тело не изменились. Файл называет поле `path` receipt (это может быть `TASK-NNN-<slug>.md`; принимается только файл из `tasks/` или `slices/` этого Change). Любая другая правка такого файла — нарушение envelope.

**Решения человека.** То, что пишет `deltafuse decide`, когда человек снимает или переоткрывает задачу или переоткрывает пробел Verify, проходит и до коммита - по байтам: файл, байты которого подтверждает квитанция `decide` в журнале гейтов (`kind: task` или `gap`); удалённая запись доказательств, чьи байты на базе лежат в её собственной копии в архиве переоткрытия (тот же относительный путь) с квитанцией; файл продукта, восстановленный при переоткрытии задачи, если его байты - те, что в снимке гейта `declaring` для этого пути. Запись `gap-reopen` в `transitions.jsonl` - квитанция ядра. Остальные байты судятся как прежде. `decide` по-прежнему советует закоммитить изменения перед следующим шагом.

**Структурные артефакты.** `routing.yaml`, `spec-delta.md`, `slices/*.md` и `tasks/*.md` Change проходят, даже внутри envelope, только если их байты совпадают с digest известного писателя: receipt Artifact Writer (`result_sha256` в `.deltafuse/receipts/`), `deltafuse state` (`sha256` в receipt `artifact-status`) или `decide` (`artifact_sha256` в журнале гейтов). Рукописный файл — нарушение с подсказкой команды `deltafuse artifact write` (п. 1 роадмапа).

**Корни кода.** `src/**` и `tests/**` выше означают корни кода продукта: `workflow.code_roots` из `.deltafuse/config.yaml`, если задан (например `[svc/src/**]`), иначе эти два. Hook и `deltafuse leash` судят «бесхозную» правку продукта и envelope Declare/Implement по тем же корням, что `deltafuse next` кладёт в `envelope.read` и `envelope.write`.

**Кэши интерпретатора.** Исключены только там, где кэш лежит: `__pycache__/<имя>.pyc` и собственные файлы pytest в `.pytest_cache/` (`README.md`, `.gitignore`, `CACHEDIR.TAG`, `v/**`): их пишет запуск Red- и Green-тестов, и воркер не может этого избежать. Любой другой файл в этих каталогах и `*.pyc` в другом месте судятся.

**`forbidden_paths` задачи.** На Declare и Implement `forbidden_paths` задачи сужают только её тестовую и продуктовую область. Собственные файлы Change (его `evidence/**`, `coverage.yaml`, `change.yaml`) остаются в envelope: туда пишет `deltafuse evidence`, и задача, запретившая `docs/**`, не должна превращать это в нарушение.

## Хост обязан

| Нужно | Источник | MUST |
|---|---|---|
| Список записи | `envelope.write` | Резать write-tools агента (ApplyPatch, write, edit) этими глобами. Не выдумывать лишние. |
| Пустой envelope + `leash: enforce` | `envelope` JSON `null` | Нет готового шага воркера. Не давать product-глобы (`src/**`, `tests/**`, ops/deploy; `docs/spec/**` после accepted baseline). Ждать / inspect можно. |
| Halt + envelope | `halt.kind` decision\|spec | Envelope пустой. Не открывать запись в код продукта, пока кнопки Human Gate на экране. |
| Хост не режет tools | `/run` | Всё равно звать `deltafuse leash` перед концом шага. Это не замена git hook. |
| Доска / кнопки | Другой репозиторий | UI fuse-map и кнопки Cursor **вне** `src/deltafuse/**`. Этот репозиторий UI не содержит. |

Хост не включает write-tools вне `envelope.write`, не считает null envelope «пиши куда угодно» при `enforce`, не auto-accept, не кладёт плагин Cursor / доску fuse-map в `src/deltafuse/**`.
