# Контракт снимка доски (DeltaFuse ↔ fuse-map)

[English](board-snapshot.md) | [**Русский**](board-snapshot.ru.md)

Машинная схема: [board-snapshot.schema.yaml](board-snapshot.schema.yaml) (`schema_version: 1`).

**Канон продюсера** — этот репозиторий. fuse-map пинит тот же `schema_version` у себя в `docs/contracts/`. SSOT артефактов — git продукта. Снимок — только чтение.

CLI/API появятся в [FM-001](../../backlog/product/FM-001.md) (отдельная ветка). Документ уже является pin совместимости.

`layout` обязателен в v1 (продюсер ещё не шипился; это дополнение v1, не bump на 2). Тело без `layout` — не снимок.

## Роли

| Сторона | Репозиторий | Обязанность |
|---|---|---|
| Продюсер | DeltaFuse | Отдать снимок по схеме. Не писать файлы продукта. Владеет геометрией доски (`layout`) и проекцией карточек (`changes`). |
| Потребитель | fuse-map | Рисовать только снимок. Stateless: нет склада карточек, нет сохранённых корней, нет хардкода колонок и шагов. |
| Склад | git продукта | `docs/changes/**`, архив, spec, Decisions. |

Продукт DeltaFuse = читаемый `.deltafuse/lock.yaml`. Нет lock — жёсткая ошибка, не пустая доска.

## Что можно знать fuse-map

Проектор. На запуск — пути корней продукта аргументами и по одному снимку на корень. После выхода процесса не хранить карточки, layout и корни.

| Нужно | Источник | Не источник |
|---|---|---|
| Колонки и порядок | `layout.columns` | state-machine.md, код UI, user config |
| Какие status в колонке | `layout.columns[].statuses` | Таблица свёртки в fuse-map |
| Шаги и какие колонки они соединяют | `layout.steps` | Имена skill в репо UI |
| Карточки | `changes` (`archive` только по флагу) | Разбор `docs/changes/**` в UI |
| Куда открыть Change | `card.path` + корень из аргумента | Угаданный `docs/changes/<id>` |

Карточка попадает в колонку, где `card.status` есть в `column.statuses`. Статус ни в одной колонке — не на дефолтной доске (терминалы не входят в happy-path колонки). Две колонки с одним status — невалидный снимок.

Заголовок колонки/шага: `label`, иначе `id`. `layout.steps` — легенда, не запуск skill. Только `to` — вход (intake). Только `from` — выход (archive).

## Транспорт

```text
deltafuse board <product-root> --json
deltafuse board <product-root> --json --archive
```

Stdout при `--json` — ровно один JSON (UTF-8); диагностика в stderr. Успех: exit `0`. Не продукт / битый lock: exit `≠ 0`, без «почти доски». Корни Changes — из `paths.changes` / `paths.archive` в config. Ноль записи на диск. `check-gate` на каждый CHG в v1 не гонять. `layout` не зависит от набора Changes: пустой `changes` всё равно полный `layout`.

## Совместимость

`schema_version` снимка **не** равен `schema_version` у `change.yaml` (там `2`).

Новое опциональное поле — остаётся `1`; потребитель игнорирует неизвестные ключи. Переименование / удаление / смена типа обязательного поля — bump на `2`. Неизвестный `schema_version` у потребителя — явный fail этого репо, не сканер YAML. `card.status` — непрозрачная строка только через `layout`.

## Запреты

Потребитель: не парсить `change.yaml` как контракт, когда есть `board`; не хардкодить колонки/шаги/свёртку status; не persist корней и карточек; не писать артефакты Change; не прятать `warnings`. Продюсер: не класть тела spec/request в JSON; не индекс-файл в продукте; не HTTP-демон в v1; не отдавать снимок без `layout`.

Корни продукта — только аргументы запуска.

Пример JSON — в [английской версии](board-snapshot.md).
