# Процесс и мыслитель

[English](process-and-thinker.md) | [**Русский**](process-and-thinker.ru.md)

В DeltaFuse два понятия. Их нельзя смешивать.

| Имя | English | Что это | Чем это не является |
|---|---|---|---|
| **Процесс** | Process | Машина lifecycle: семь шагов, FSM, гейты, evidence, `next`, archive | LLM. Человек, который заполняет файлы Change. Второй workflow «для людей» |
| **Мыслитель** | Thinker | LLM **или** человек, который пишет артефакты Change текущего шага | Тот, кто выбирает следующий шаг, классифицирует Red/Green или принимает Decisions |

Исполняемый Процесс — **ядро** (kernel CLI): `deltafuse next`, `evidence`, `check-gate`, `archive`, `board`. Оно читает git продукта. Оно не выдумывает claims, текст спецификации, TASK и код продукта. Оно не вызывает модель.

Мыслитель читает то, что разрешает шаг, и пишет только файлы этого шага. Одни и те же пути для LLM и человека. Skills (`process/skills/*/SKILL.md`) привязывают мыслителя к LLM. `deltafuse next --human` привязывает тот же шаг к человеку. Второго lifecycle нет.

```text
Мыслитель  --только файлы Change-->  git продукта
Процесс    --next / evidence / check-gate / archive-->  git продукта
Процесс    --halt, если гейт не прошёл-->  Мыслитель
```

## Human Gate — не мыслитель

**Human Gate** (DEC / accept spec / merge) — остановка Процесса. Пройти её может только человек. Заполнить `/analyze` или `/declare` вручную — работа мыслителя. Принять `DEC-*` — работа Gate. Один человек, две шляпы. Процесс не auto-accept Gate. Мыслитель не выдаёт Gate за шаг.

## Как не говорить

| Не использовать | Говорить |
|---|---|
| Worker / воркер как имя роли верхнего уровня | Мыслитель / Thinker |
| Оркестратор внутри модели | Процесс (`deltafuse next`) |
| LLM adapter как имя роли | Мыслитель (LLM) — skill это привязка |
| Отдельный процесс для людей | Тот же Процесс, человеческий мыслитель |
| Human Gate = мыслитель | Human Gate = остановка Процесса |
