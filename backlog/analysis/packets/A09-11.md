## Вопрос и гипотеза

**Вопрос:** Измерить локальное исполнение S11: Два Change и удаление функции — выполнено ли проверяемое условие результата ниже?

**Рабочая гипотеза:** Зафиксированный локальный профиль способен выполнить заданный сценарий по всем фазам в принятом бюджете и пройти независимые проверки результата.

**Альтернативное объяснение:** Успех обеспечен ручным исправлением, утечкой oracle или пропущенной фазой; неудача обусловлена интеграцией/профилем, а не контрактом DeltaFuse.

До эксперимента привязать гипотезу к одному инварианту или case и ID критерия A01. Для подготовительных карточек проверяется полнота подготовки; итог соответствия DeltaFuse не предполагается.

## Ограниченные входы

- `backlog/analysis/experiments/protocol.md :: holdout и stopping`.
- `backlog/analysis/experiments/A03-03/profile.md :: профиль`.
- `backlog/analysis/experiments/cases/S11/manifest.yaml :: один case`.

Также: только handoff зависимостей и секция A09 плана. Пути указаны от корня репозитория. Результаты зависимостей читать после их появления. Дополнительные чтения — определения указанных символов/refs и первичное evidence из handoff, с записью диапазонов в manifest.

**Бюджет на вызов:** до 6000 токенов полного prompt, резерв ответа 2000; handoff до 400. Лимит предварительный до A03 и уменьшается до измеренного лимита профиля. При переполнении создать ограниченные дочерние карточки до исполнения, не усекать вход.

## Метод и проверяемый результат

**Метод:** Реальные holdout/стресс-прогоны локальной LLM.

На ornith-1.5-35b-a3b через LM Studio проверено: Конфликты, инвалидация и актуальность spec после последовательного изменения. ≥3 повторов на case/config; для растущих размеров остановка у первой границы и её уточнение. Записаны метрики каждой фазы как в A09-01, независимая оценка spec/code/tests, неудачи и ручные исправления. Holdout не используется для настройки prompts.

**Условие завершения:** указанное условие проверено, записаны наблюдения и ограничения; есть verdict с evidence и handoff для зависимых задач. Нарушение условия фиксируется как `fail`/finding, а не скрывается; отсутствие обязательного доступа — `blocked`. Для допустимого пропуска платформы — обоснованный `not-tested`.

## Выход и передача

Создать по факту исполнения:

- `backlog/analysis/experiments/A09-11/manifest.yaml` — ревизия, точные inputs, метод, команды/параметры, бюджеты и файлы результата.
- `backlog/analysis/experiments/A09-11/result.md` — ожидаемое/наблюдаемое, verdict, evidence, ограничения и компактный handoff.
- Логи, request/response для реального LLM-вызова и строки общих артефактов, названных в условии результата; finding по формату плана при наличии оснований.

Handoff: вывод; IDs критериев/инвариантов/claims; ссылки на доказательства; нерешённые вопросы; пригодность результата для зависимых задач. После исполнения обновить статус и следующую задачу в индексе.

**Результат пока отсутствует: карточка только подготовлена.**
