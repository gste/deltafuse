## Вопрос и гипотеза

**Вопрос:** Зафиксировать ревизию и границы аудита — выполнено ли проверяемое условие результата ниже?

**Рабочая гипотеза:** Для указанного результата можно получить воспроизводимые входы и независимый критерий проверки без загрузки всего направления в одну сессию.

**Альтернативное объяснение:** Наблюдение объясняется неполным входом, особенностью окружения или слишком слабым oracle; отсутствие найденного дефекта не подтверждает гарантию.

До эксперимента привязать гипотезу к одному инварианту или case и ID критерия A01. Для подготовительных карточек проверяется полнота подготовки; итог соответствия DeltaFuse не предполагается.

## Ограниченные входы

- `AGENTS.md :: Mandate, Change rules`.
- `VERSION :: значение`.
- `pyproject.toml :: project`.
- `backlog/analysis-plan.md :: раздел 1`.

Отдельно инвентаризировать существующие локальные логи `backlog/analysis/experiments/EX-001/` (они исключены правилом `*.log`). Проверить ревизию и пригодность по одному логу; не считать их автоматически результатом этой очереди и не перезаписывать.

Также: только handoff зависимостей и секция A00 плана. Пути указаны от корня репозитория. Результаты зависимостей читать после их появления. Дополнительные чтения — определения указанных символов/refs и первичное evidence из handoff, с записью диапазонов в manifest.

**Бюджет на вызов:** до 6000 токенов полного prompt, резерв ответа 2000; handoff до 400. Лимит предварительный до A03 и уменьшается до измеренного лимита профиля. При переполнении создать ограниченные дочерние карточки до исполнения, не усекать вход.

## Метод и проверяемый результат

**Метод:** Read-only инвентаризация git и окружения.

В baseline.md записаны HEAD, staged/unstaged/untracked изменения, время и границы аудита; изменения подготовки задач отделены от исследуемого поведения.

**Условие завершения:** указанное условие проверено, записаны наблюдения и ограничения; есть verdict с evidence и handoff для зависимых задач. Нарушение условия фиксируется как `fail`/finding, а не скрывается; отсутствие обязательного доступа — `blocked`. Для допустимого пропуска платформы — обоснованный `not-tested`.

## Выход и передача

Создать по факту исполнения:

- `backlog/analysis/experiments/A00-01/manifest.yaml` — ревизия, точные inputs, метод, команды/параметры, бюджеты и файлы результата.
- `backlog/analysis/experiments/A00-01/result.md` — ожидаемое/наблюдаемое, verdict, evidence, ограничения и компактный handoff.
- Логи, request/response для реального LLM-вызова и строки общих артефактов, названных в условии результата; finding по формату плана при наличии оснований.

Handoff: вывод; IDs критериев/инвариантов/claims; ссылки на доказательства; нерешённые вопросы; пригодность результата для зависимых задач. После исполнения обновить статус и следующую задачу в индексе.

**Результат пока отсутствует: карточка только подготовлена.**
