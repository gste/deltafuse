## Вопрос и гипотеза

**Вопрос:** Каждый пункт [parking/design-questions.md](../parking/design-questions.md) получил `accept` / `defer` / `reject` с привязкой к критерию A01 и входом в [A12-03](A12-03.md)?

**Рабочая гипотеза:** Отложенные идеи (ширина борозды, tokenizer-калибровка, retrieval vs счёт) либо становятся проверяемыми пунктами roadmap, либо явно отвергаются, чтобы не расползтись в оверфит под ornith.

**Альтернативное объяснение:** Идея уже покрыта finding (F-002/F-003/F-009) или четырьмя вопросами A12-02; отдельный пункт roadmap не нужен.

До эксперимента привязать каждый `Q-NNN` к критерию A01. Карточка не меняет контракты фреймворка.

**Бюджет на вызов:** до 6000 токенов полного prompt, резерв ответа 2000; handoff до 400.

## Метод и проверяемый результат

**Метод:** Разбор parking-листа, не новый эксперимент с моделью.

Для каждого `Q-NNN`: вердикт `accept` / `defer` / `reject`; затронутый слой (docs / skill / schema / CLI / lock); минимальный вариант vs ornith-оверфит; измеримый эффект; как проверить после внедрения. `accept` даёт кандидат P0–P3 для A12-03. Finding не превращать во второй Q.

**Условие завершения:** в parking у всех `Q-*` не `parked`; есть result/handoff для A12-03; ни один пункт не внедрён «заодно» в этой карточке.
