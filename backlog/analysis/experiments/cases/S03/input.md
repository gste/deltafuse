# Баг-репорт: Неверный расчет дробного остатка токенов (S03)

В текущей реализации `TokenBucketLimiter` обнаружен дефект при работе с дробными значениями refill_rate.

Симптомы:
При инициализации `TokenBucketLimiter(capacity=10, refill_rate=0.5)` после ожидания в 3 секунды восстанавливается 1 токен вместо положенных 1.5 токенов, так как в формуле восстановления используется целочисленное деление `int(elapsed * refill_rate)` вместо вычисления float с сохранением дробного остатка для последующих запросов.

Требования:
1. Исправить расчет восстановления баланса: токены должны накапливаться с плавающей точкой (`float`), чтобы дробные доли не терялись между последовательными вызовами.
2. Метод `consume` должен корректно списывать целочисленное или дробное число токенов.
3. Спецификация `docs/spec/security/ratelimit.md` УЖЕ требует точного учета времени и пропорционального пополнения («tokens MUST be refilled proportionally to elapsed time»), поэтому спецификация верна и НЕ ДОЛЖНА изменяться (`spec unchanged`).
4. На этапе Target создать падающий тест (Red), воспроизводящий накопление дробных токенов при малых интервалах времени.
