# Результат эксперимента A08-14

- **ID карточки:** A08-14
- **Ревизия:** `ca3cd73`
- **Критерии:** `PROC-002`, `PROC-003`, `PROC-005`
- **Вердикт:** **pass** (сценарий S10: Прерывание и повторная нарезка подготовлен в holdout-сплите с оракулом возобновления без потери и дублирования)

## Ожидаемое поведение

1. **Характер сценария S10 (Interrupt / Resume / Re-slice / Holdout)**: исходный запрос добавляет историю `consume` в `security.ratelimit`. Исполняющая модель видит только `input.md`. Останов после Red для `TASK-001`, повторный запуск того же Change, затем follow-up CR-003 (файловая персистенция) с повторной нарезкой.
2. **Оракулы процесса**: один Change ID; Red `TASK-001` сохранён; задачи не дублируются; отменённые задачи остаются на диске; реализованная работа `TASK-001` не теряется; `converged` допускает `cancelled`/`superseded`.
3. **Мутации**: новый Change при resume, дубликат задач, потеря Red, удаление файлов отменённых задач, сброс реализации, блокировка converge (регрессия F-005).

## Наблюдаемое поведение

1. Артефакты созданы в [cases/S10/](../cases/S10/).
2. Сценарий включен в holdout-выборку для A09-10.
3. `MockChangeBuilder` закрывает линейный happy-path одного Change; протокол interrupt/resume/re-slice задан в `manifest.yaml` для харнесса A09, без отдельного метода builder.

## Ограничения

- Подготовка не исполняет прерывание процесса. A09-10 обязан инжектировать checkpoint и follow-up отдельно от `input.md`.
- Oracle намеренно ожидает схождение при `cancelled`/`superseded`. При неисправленном [F-005](../../../findings/F-005.md) прогон A09-10 должен дать `fail` по `test_converge_with_cancelled_tasks`, а не ослаблять оракул.
