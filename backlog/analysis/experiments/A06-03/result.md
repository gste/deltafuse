# Результат эксперимента A06-03

- **ID карточки:** A06-03
- **Ревизия:** `50a0635`
- **Критерии:** `SPEC-006` (Single Source of Truth), `PROC-001` (Lock Traceability), `PROC-003` (Crash Resilience & Re-entrance)
- **Вердикт:** **pass** (идемпотентность upgrade, защита пользовательских файлов, изоляция активных Changes и защита lock подтверждены)

## Ожидаемое поведение

1. **Идемпотентность и повторный запуск (Idempotent Upgrade)**:
   - Повторный запуск инсталлятора на уже инициализированном репозитории не должен повреждать структуру, сбрасывать пользовательские настройки или дублировать файлы.
2. **Сохранение пользовательских модификаций**:
   - Шаблонные файлы, в которые пользователь вносит продуктовые изменения (`AGENTS.md`, `docs/spec/_capabilities.yaml`, `docs/decisions/*`, `CHANGELOG.md`), не должны перезаписываться при повторной установке (`_copy_template_file: if dst.exists(): return False`).
   - Собственные навыки пользователя (без маркера `.deltafuse-generated.yaml`) в директориях адаптеров (`.agents/skills/*`, `.cursor/skills/*`) должны сохраняться нетронутыми.
3. **Безопасность активных Change-пакетов**:
   - Активные и завершённые изменения в `docs/changes/**` и `docs/archive/**` не затрагиваются процедурой обновления.
4. **Контроль несовместимости Lock**:
   - При попытке наката обновления на lock с отличающимся хэшем/версией без флага `--force` инсталлятор должен аварийно останавливаться с понятной ошибкой:
     `"A different DeltaFuse lock already exists. Rerun with --force for an explicit upgrade."`

## Наблюдаемое поведение

1. **Защита от случайной перезаписи несовпадающего lock**:
   - Тест `test_force_upgrade_with_modified_lock`: подмена хэша в `lock.yaml` без `--force` вызывает строго типизированное исключение `InstallationError` с указанием необходимости явного подтверждения обновления.
   - Запуск с флагом `--force` корректно производит обновление версии и хэша в `lock.yaml` и обновляет сгенерированные навыки.
2. **Сохранение продуктовых файлов и пользовательских навыков**:
   - При симуляции кастомного содержимого `AGENTS.md` и `_capabilities.yaml` инсталлятор сообщает `Preserving existing ...` и оставляет файлы без изменений (`assert read_text() == custom`).
   - Пользовательский навык `.agents/skills/custom-skill` без маркера генерации полностью сохраняется при форсированном обновлении фреймворка (`if not marker_file.is_file(): continue`).
   - Активный пакет `docs/changes/CHG-001` полностью сохраняет своё состояние и файлы запросов.
3. **Устойчивость к сбоям и восстановление (Crash Resilience)**:
   - Инсталлятор не выполняет деструктивной очистки всего каталога продукта.
   - Сгенерированные навыки обновляются изолированно директория за директорией.
   - В случае прерывания процесса пользовательские данные не теряются, а повторный запуск команды `deltafuse init --force` безопасно доводит процесс обновления до конца (реентрантность $100\%$).

## Ограничения

- Запись `lock.yaml` и `config.yaml` выполняется напрямую через `Path.write_text` без предварительной записи во временный файл (`.tmp`) с последующим атомарным `os.replace`. При аппаратном сбое питания точно в момент записи `lock.yaml` файл может оказаться усечённым, однако повторный запуск `init --force` полностью восстанавливает его.

- **Результат**: Механизмы обновления (upgrade), идемпотентность, безопасность данных пользователя и реентрантность верифицированы.
- **Готовность к переходу**: Разрешён переход к задаче [A06-04](packets/A06-04.md) — «Проверить archive после прерывания».
