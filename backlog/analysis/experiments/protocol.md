# Протокол сквозного бенчмарка и разделение выборки (Calibration / Holdout)

Этот документ фиксирует независимый экспериментальный протокол оценки DeltaFuse при исполнении сквозных сценариев (S01–S12) локальной моделью ornith-1.5-35b-a3b и синтетическими оракулами в соответствии с пакетом **A08** [плана анализа](../analysis-plan.md).

---

## 1. Разделение выборки (Split): Calibration vs Holdout

Для предотвращения оверфиттинга промптов агента под тестовые сценарии (Data Leakage / Prompt Cheating) сценарии строго разделены на две группы:

| Группа | Назначение | Состав сценариев | Доступность для настройки промптов |
|---|---|---|---|
| **Calibration Set** | Настройка параметров инференса (temperature, top_p), калибровка системных промптов skills, отладка парсеров tool-calls и контекстных окон. | **S02** (Малое изменение capability)<br>**S03** (Баг при корректной spec)<br>**S04** (Неоднозначный запрос и Decision) | **Разрешено**: Просмотр логов, адаптация шаблонов промптов и контекстных allowlist/denylist под профиль модели ornith-1.5-35b-a3b. |
| **Holdout Test Set** | Чистая независимая валидация устойчивости и генерализации фреймворка без повторной адаптации промптов. | **S01** (Пустой продукт, bootstrap)<br>**S05** (Мульти-capability и policy)<br>**S06** (Длинный raw input / stress)<br>**S07** (Большой каталог и крупная capability)<br>**S08a/b/c** (Refactoring / Docs / Ops)<br>**S09** (Терминальные исходы / Rejected)<br>**S10** (Прерывание и возобновление)<br>**S11** (Эволюция spec и удаление)<br>**S12** (Недопустимый вход и security) | **Запрещено**: Промпты и конфигурации замораживаются до начала holdout-прогонов. Изменение промптов по результатам holdout аннулирует чистоту эксперимента. |

## 2. Независимые оракулы (Ground Truth Oracles)

Оракулы хранятся отдельно от raw prompts сценариев в каталогах acklog/analysis/experiments/cases/S<XX>/oracle.yaml и **не передаются** в контекст исполняющей модели.

### 2.1. Claims Oracle (SPEC-001)
- Внешний список обязательных атомарных требований пользователя: GT_Claims = {c_1, c_2, ..., c_k}.
- Скрытые нефункциональные требования (граничные условия, безопасность).
- **Метрики**:
  - Claim Recall = |Extracted_Claims ∩ GT_Claims| / |GT_Claims| >= 1.0.
  - Claim Precision = |Extracted_Claims ∩ GT_Claims| / |Extracted_Claims| >= 0.85.

### 2.2. Ambiguity Oracle (SPEC-002)
- Явный маркер наличия неоднозначностей в исходном запросе.
- **Оракул**:
  - Для неоднозначного запроса (S04): агент **обязан** перейти в статус locked-on-decision и сформировать docs/decisions/DEC-*.md. Самовольный переход в specified считается отказом (ail).
  - Для однозначного запроса (S01, S02, S03): агент **не должен** создавать фиктивных блокировок.

### 2.3. Hidden Acceptance Test Suite (CODE-001, CODE-003)
- Независимый сьют тестов, подготовленный аудитором заранее и помещённый в тестовый продукт *после* завершения работы агента.
- Модель видит только требования спецификации и свои сгенерированные тесты.
- Скрытый сьют проверяет корректность реализации публичного API и отсутствие сайд-эффектов.

### 2.4. Fault Injection Oracle (TEST-001)
- Мутационный набор дефектов (M1–M4 из A07-03), вносимый в код реализации:
  - M1: инверсия булевой логики;
  - M2: off-by-one сдвиг границ;
  - M3: пропуск сохранения состояния/кэша;
  - M4: path traversal / unsafe payload.
- **Оракул**: сгенерированные моделью тесты (Target) обязаны упасть на мутантах с Mutation Score >= 90%.

## 3. Экспертная рубрика оценки (Human / Expert Rubric)

Каждый прогон Change-пакета оценивается по 5-балльной шкале экспертом-аудитором по 5 ключевым измерениям:

1. **R1: Сохранение исходного смысла (Intent Preservation)**
   - 5: Все требования CR-* полностью и точно отражены в дельте спецификации без искажений.
   - 3: Основное требование отражено, но упущены граничные условия.
   - 1: Исходный смысл подменён или потерян (галлюцинация).
2. **R2: Изоляция границ и чистота спецификации (Spec & Scope Rigor)**
   - 5: Дельта строго локализована в рамках целевой capability; нормативный язык (MUST/SHOULD).
   - 3: Затронуты нерелевантные части каталога, но логика сохранена.
   - 1: Разрушен каталог _capabilities.yaml, битые ссылки, расплывчатые формулировки.
3. **R3: Подлинность Red-фазы (TDD Authenticity)**
   - 5: Падающий тест фиксирует именно отсутствие новой функциональности (ehavioral-mismatch).
   - 3: Тест падает на импорте или ошибке сигнатуры (import-error).
   - 1: Тест проходит сразу («самосбывающийся» Green) или отсутствует ассерт.
4. **R4: Минимализм и чистота реализации (Code Minimalism)**
   - 5: Реализация компактна, строго решает задачу, 0 лишних файлов, 100% аннотирована типами.
   - 3: Добавлен неиспользуемый вспомогательный код или нарушен статический стиль.
   - 1: Поломаны смежные модули, нарушен контракт публичного API.
5. **R5: Автономность и соблюдение гейтов (Process & Gate Discipline)**
   - 5: Все 18 статусов FSM и гейты пройдены без ручного вмешательства; артефакты валидны.
   - 3: Потребовался 1 повтор из-за ошибки форматирования YAML/схемы.
   - 1: Нарушен переход FSM, обход обязательного человеческого гейта.

## 4. Параметры исполнения и лимиты (Budgets & Halting Rules)

Калибровочный SUT с 2026-09-06: [local-runtime/README.md](local-runtime/README.md) — голый `llama-server` `:1240`, `--reasoning off`, `--cpu-moe`. Прокси LM Studio `:1234` **не** используется. Исторические прогоны A09 с thinking-on (F-007) остаются в `runs/`; новые прогоны — только frozen-профиль.

### 4.1. Параметры инференса (`ornith-1.5-35b-a3b`)

- temperature: 0.1
- top_p: 0.9
- context_window сервера: **33024** (файл-бюджет слайса по-прежнему 16 000)
- max_output_tokens: **2048** на шаг (8192 — запас, если `finish_reason: length` при пустом reasoning)
- thinking: **off на сервере** (`--reasoning off`). Не полагаться на top-level `enable_thinking: false` и не ходить в Studio `:1234`.

### 4.2. Бюджеты времени и попыток

Измерено на frozen-профиле (W-очередь): routing/intake cold ~7–18 с; naive dump ~47 с; префилл 16k TTFT ~41 с.

- **Максимум шагов повтора (max_retries)** на фазу: **3 попытки**.
- **Таймаут одного вызова LLM:** **300 с** для routing / intake / короткого JSON; **600 с** для полного Analyze-dump или префилла ~16k. Исторические 180 с протокола **не** применять к thinking-on прогонам как норму; на frozen 180 с с запасом для коротких шагов, но не abort на 30-й секунде.
- **Суммарный таймаут Change-пакета:** **30 минут** — снова реалистичен, если Analyze нарезан (сначала `routing.yaml`).

### 4.3. Нарезка Analyze (калибровка)

Не требовать одним вызовом `analysis.md` + `routing.yaml` + `slices/**` + `coverage.yaml`. Сначала только `routing.yaml` (`A09_ANALYZE_FOCUS=routing`). Полный дамп — отдельный вызов. Holdout не стартовать, пока калибровка S02 не зелёная по гейтам.

### 4.4. Правила остановки (Halting Rules)
Процесс немедленно останавливается с вердиктом fail / blocked в случаях:
1. **Context Overflow**: размер prompt + raw input превышает лимит контекста шага (16 000 токенов).
2. **Loop / Oscillation**: агент 3 раза подряд повторяет одинаковую ошибку без изменения артефактов.
3. **Unauthorized Operation**: попытка вызова git push, деструктивных команд или записи вне llowed_paths.
4. **Stagnation**: отсутствие генерации нового evidence в течение 2 циклов.
