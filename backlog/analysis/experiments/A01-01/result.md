# A01-01 — Критерии качества спецификации

**Verdict: `pass` для SPEC-001..SPEC-007.** На ревизии `60ea40438b0142797848356c660ab88286565e7d` (рабочий HEAD `852f5ef3a1eb1d81f1ba4f74d0ae86c4bc0b3967`) в нормативном документе [backlog/criteria.md](../../../criteria.md) формализовано дерево независимых, фальсифицируемых критериев качества спецификации в рамках пакета A01 [плана анализа](../../analysis-plan.md).

Для каждого критерия зафиксированы:
1. Уникальный ID и наименование;
2. Объективный оракул (наблюдаемый инвариант / артефакт);
3. Воспроизводимый метод измерения / верификации;
4. Строгий числовой или логический порог;
5. Инженерное обоснование порога на основе архитектуры DeltaFuse.

| ID | Критерий | Oracle | Метод измерения | Порог | Основание |
|---|---|---|---|---|---|
| **SPEC-001** | Сохранение смысла входа (Intent Preservation) | Трассируемость `request.md :: CR-*` <-> `coverage.yaml` <-> `spec-delta.md` / `docs/spec/**` | Сверка покрытия claims: `|Mapped(CR)| / |Total(CR)| * 100%` | 100% покрытие; 0 искажений; 0 незапрошенных требований | Исключение искажения намерений пользователя и gold-plating на фазе Specify |
| **SPEC-002** | Выявление неоднозначностей (Ambiguity Resolution) | Статусы `Ambiguous`/`Capability-Gap` в `routing.yaml`; создание `docs/decisions/DEC-*` | Стресс-тестирование на противоречиях; аудит обязательности Human Gate | 0 скрытых допущений агента; 100% развилок зафиксированы в `DEC-*` и одобрены человеком | Предотвращение скрытого дрифта архитектуры и несоответствия ожиданий |
| **SPEC-003** | Нормативность языка (Normative Rigor) | Нормативные модальные глаголы RFC 2119 (MUST, MUST NOT, SHOULD, MAY); отсутствие расплывчатости | Лексический и синтаксический анализ формулировок требований | 100% требований содержат нормативные операторы и проверяемые условия | Ненормативный язык делает спецификацию недоказуемой и размывает границы приемки |
| **SPEC-004** | Проверяемость и полнота оракула (Testability & Oracle) | Наличие воспроизводимого условия верификации для генерации Red-теста до кода | Инспекция связки требование -> test oracle; генерация падающего теста | 100% требований имеют воспроизводимый оракул для Red-теста | Требование без оракула порождает самосбывающиеся тесты и ложную верификацию |
| **SPEC-005** | Навигация и каталогизация (Navigability & Context) | Регистрация модулей в `docs/spec/_capabilities.yaml`; DAG без циклов; context limits | Валидация каталога схемой, проверка графа связей, замер среза контекста | 0 битых ссылок; 0 модулей вне каталога; 0 циклов; срез <= 16k токенов / 24 файлов | Возможность изолированной загрузки среза требований в контекст локальной LLM |
| **SPEC-006** | Единственность источника истины (Single Source of Truth) | `docs/spec/**` — единственный источник; дельты только через `spec-delta.md` | Сверка фактического diff с `spec-delta.md`; валидация layout на отсутствие runtime-путей | 0 расхождений; 0 альтернативных спецификаций в репозитории | Исключение рассинхронизации требований между кодом, тестами и документацией |
| **SPEC-007** | Актуальность при эволюции (Evolution Integrity) | Явная фиксация `modify` и `remove` при цепочке изменений `CHG-*` | Регрессионная валидация каталога и ссылочной целостности архива `docs/archive/**` | 0 противоречий между версиями возможностей; 0 мертвых/устаревших требований | Предотвращение деградации («гниения») спецификации при длительной эволюции |

Полное описание критериев приведено в [backlog/criteria.md](../../../criteria.md).
