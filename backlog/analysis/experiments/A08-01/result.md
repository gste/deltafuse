# Результат эксперимента A08-01

- **ID карточки:** A08-01
- **Ревизия:** `4bf7fc3`
- **Критерии:** `PROC-004` (Bounded Execution & Context), `PROC-007` (Resource Efficiency), `TEST-001` (Fault Detection Power)
- **Вердикт:** **pass** (архитектура eval harness, изоляция mock/real провайдеров и интерфейс интеграции с локальной моделью подтверждены)

## Ожидаемое поведение

1. **Архитектурное разделение eval-провайдеров**:
   - Подсистема LLM Evals (`src/deltafuse/evals/`) должна обеспечивать чистое абстрагирование логики оценки (`runner.py`, `metrics.py`) от конкретного источника генерации Change-пакетов через базовый класс `LLMProvider`.
   - Детерминированные сценарии CI (`MockLLMProvider`: `golden`, `schema_violation`, `fsm_violation`, `routing_mismatch`, `claim_hallucination`) должны исполняться оффлайн без сетевых зависимостей и без токенов API.
2. **Интеграция с локальной LLM (`ornith-1.5-35b-a3b`)**:
   - Возможность подключения локального инференса (LM Studio на `http://127.0.0.1:1234/v1`, подтверждённого в A03-03 и A03-04) без внесения изменений в runtime DeltaFuse.
   - Использование `CallableLLMProvider` или адаптера локального провайдера для сквозного прогона синтетических и holdout сценариев.
3. **Метрики качества бенчмарка**:
   - Harness должен рассчитывать:
     - `Schema Compliance Rate` (% пакетов без ошибок Draft 2020-12);
     - `Gate Pass Rate` (% пакетов, успешно преодолевших целевой FSM-гейт);
     - `Routing Accuracy` (% совпадений с целевой primary capability);
     - `Claim Extraction Avg F1` (точность извлечения требований `CR-*`).

## Наблюдаемое поведение

1. **Работоспособность детерминированного Eval Harness**:
   - Запуск `run_eval(EvalDataset.get_default_dataset(), MockLLMProvider("golden"))` на 6 эталонных кейсах:
     - 6 из 6 кейсов успешно прошли проверку (`PASS`, 100.0%).
     - `Schema Compliance Rate`: 100.0%.
     - `Gate Pass Rate`: 100.0%.
     - `Routing Accuracy`: 100.0%.
     - `Claim Extraction Avg F1`: 1.0000.
     - Время полного прогона: **291.42 мс**.
2. **Механизм интеграции с LM Studio**:
   - `RealLLMProvider` в базовом коде фреймворка ориентирован на внешние API (`OPENAI_API_KEY`, `DELTAFUSE_API_KEY`).
   - Для локальной модели `ornith-1.5-35b-a3b` в LM Studio доступен OpenAI-совместимый эндпоинт `http://127.0.0.1:1234/v1/chat/completions`, который легко подключается через `CallableLLMProvider` или установку `OPENAI_BASE_URL="http://127.0.0.1:1234/v1"` и `OPENAI_API_KEY="lm-studio"`.
   - Это гарантирует полную изоляцию: runtime DeltaFuse остаётся неизменным, а эксперименты пакетов A08 и A09 выполняются поверх стандартизированного интерфейса.

## Ограничения

- Вызовы локальной LLM `ornith-1.5-35b-a3b` занимают от 60 до 400 секунд на один полный запрос генерации пакета (как измерено в A03-04). Поэтому в рамках юнит- и CI-тестов используется `MockLLMProvider`, а реальные прогоны вынесены в специализированные пакеты (A09).
