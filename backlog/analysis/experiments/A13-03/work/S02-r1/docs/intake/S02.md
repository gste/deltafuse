# Запрос пользователя на малое изменение существующей capability (S02)

В сервисе Rate Limiter (`security.ratelimit`) необходимо добавить поддержку временной блокировки ключа при превышении лимита (Cool-down penalty).

Требования:
1. Добавить опциональный параметр `penalty_seconds` (по умолчанию 0.0) при инициализации `TokenBucketLimiter`.
2. Если `penalty_seconds > 0`:
   - При неудачной попытке `consume` (когда токенов недостаточно), ключ переходит в состояние блокировки на `penalty_seconds`.
   - Любые вызовы `consume` для заблокированного ключа в течение периода штрафа ДОЛЖНЫ возвращать `False` немедленно, даже если за это время накопились токены.
3. По истечении `penalty_seconds` блокировка снимается автоматически при следующем запросе, и возобновляется обычная логика списания.
4. Метод `is_blocked(key)` ДОЛЖЕН возвращать `True`, если ключ сейчас находится под действием штрафа, и `False` в противном случае.
5. Не ломать обратную совместимость: существующий код без `penalty_seconds` должен работать по прежним правилам.
