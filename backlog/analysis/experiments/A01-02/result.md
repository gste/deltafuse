# A01-02 — Критерии качества кода

**Verdict: `pass` для CODE-001..CODE-007.** На ревизии `60ea40438b0142797848356c660ab88286565e7d` (рабочий HEAD `89851261d7634f4be2db65c630f55cf5fe878c77`) в нормативном документе [backlog/criteria.md](../../../criteria.md) формализовано дерево независимых, фальсифицируемых критериев качества кода в рамках пакета A01 [плана анализа](../../analysis-plan.md).

Для каждого критерия зафиксированы:
1. Уникальный ID и наименование;
2. Объективный оракул (наблюдаемый инвариант / артефакт);
3. Воспроизводимый метод измерения / верификации;
4. Строгий числовой или логический порог;
5. Инженерное обоснование порога на основе архитектуры DeltaFuse и ограничений локальных моделей.

| ID | Критерий | Oracle | Метод измерения | Порог | Основание |
|---|---|---|---|---|---|
| **CODE-001** | Соответствие принятой спецификации (Spec Compliance) | Трассируемость `TASK-NNN.md :: spec_refs` <-> сигнатуры и логика; assertions целевого теста задачи | Инспекция diff задачи против `spec_refs`; сопоставление API и контрактов со спецификацией | 100% покрытие требований задачи; 0 расхождений со спецификацией | Отклонения от спецификации разрушают предсказуемость поведения системы |
| **CODE-002** | Соблюдение границ изменений (Scope & Boundary Isolation) | Список изменённых файлов в git diff; соответствие `allowed_paths` и отсутствие `forbidden_paths` | Автоматическая проверка diff задачи: `Paths(Diff) ⊆ allowed_paths` и `Paths(Diff) ∩ forbidden_paths = ∅` | 100% путей внутри `allowed_paths`; 0 путей в `forbidden_paths`; 0 побочных изменений | Предотвращение межмодульных конфликтов, неявных регрессий и раздувания контекста LLM |

| **CODE-004** | Минимализм и неспекулятивность (Minimal Implementation) | Объём кода достаточен только для удовлетворения теста задачи; отсутствие dead code | Анализ покрытия новых строк тестом (line coverage >= 90%); статический анализ недостижимого кода | 0 спекулятивных фич «про запас»; 0 недостижимых ветвей; покрытие нового кода >= 90% | Спекулятивный код раздувает контекст модели, удорожает поддержку и скрывает ошибки |
| **CODE-005** | Статическая типизация и чистота контрактов (Type Safety) | Отсутствие ошибок статических анализаторов (mypy, pyright, ruff/flake8); наличие аннотаций типов | Прогон линтеров и type checker; замер доли типизированных интерфейсов: `|Typed| / |Total| * 100%` | 0 ошибок типизации и критических ворнингов; 100% аннотация публичных сигнатур | Локальная LLM точно оперирует интерфейсами по сигнатурам без чтения их реализации |
| **CODE-006** | Эксплицитность обработки ошибок (Explicit Error Handling) | Отсутствие silent failure (`except: pass`, catch-all без проброса); типизированные исключения | Поиск bare except через AST/ripgrep; сверка типов исключений с оракулом `TASK-NNN.md` | 0 случаев маскирования ошибок; 100% ошибочных путей возбуждают документированные ошибки | Подавление исключений маскирует дефекты и приводит к непредсказуемым отказам |
| **CODE-007** | Сопровождаемость и модульность (Maintainability & Quality) | Cyclomatic complexity <= 10; отсутствие циклических импортов модулей; соблюдение SRP | Расчёт метрик сложности (mccabe/radon); анализ графа модульных зависимостей на ацикличность | Cyclomatic complexity <= 10 на функцию; 0 циклических импортов; длина функции <= 50 строк | Монолитный спагетти-код не помещается в ограниченный контекст локальной модели |
