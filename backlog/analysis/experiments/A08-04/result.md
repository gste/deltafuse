## Ожидаемое поведение

1. **Характер сценария S02 (Small capability delta / Calibration)**:
   - Сценарий моделирует локальное расширение уже существующей capability (`security.ratelimit`), добавляя механизм штрафной временной блокировки (cool-down penalty).
   - Агент должен продемонстрировать высокую избирательность: загрузка только целевой спецификации `docs/spec/security/ratelimit.md` без раздувания контекста; модификация кода строго внутри `allowed_paths`; сохранение обратной совместимости (Zero Regressions Guarantee).
2. **Внешние оракулы и границы изменений**:
   - `oracle.yaml`: зафиксированы 3 атомарных требования (`CR-001: Penalty Parameter`, `CR-002: Lockout Behavior`, `CR-003: Auto-unblock & Query`) с явными `allowed_paths` и `forbidden_paths`.
   - Скрытый приёмочный сьют `hidden_suite/test_acceptance.py`: проверяет сохранение прежнего API без штрафа и строгое соблюдение временных рамок блокировки (`test_penalty_lockout_and_expiration`).
   - Мутационный набор `fault_suite/mutations.yaml`: содержит 4 мутации (M1–M4) на отлов утечки состояния и поломки обратной совместимости.

## Наблюдаемое поведение

1. В каталоге [backlog/analysis/experiments/cases/S02/](../cases/S02/) созданы артефакты сценария:
   - `input.md`: текст пользовательского запроса на расширение функциональности без раскрытия внутренних деталей фреймворка;
   - `manifest.yaml`: метаданные сценария (`group: calibration`, `target_capability: security.ratelimit`, `target_gate: converged`);
   - `oracle.yaml`: внешний эталон claims и запрет затрагивания смежных модулей (`forbidden_paths: src/auth/**`);
   - `hidden_suite/test_acceptance.py`: независимый сьют для финальной приёмки;
   - `fault_suite/mutations.yaml`: эталон мутаций для аудита оракула тестов.
2. Сценарий отнесён к `calibration`-выборке и готов для калибровки промптов локальной модели в задаче A09-01.
