# Результат эксперимента A03-02

- **ID карточки:** A03-02
- **Ревизия:** `7299adc76d84f4dc5492ff9e491c28ccebb25867`
- **Критерии:** `PROC-004` (Bounded Execution & Context), `CODE-006` (Robust Error Handling & Security)
- **Вердикт:** **fail** (обнаружены граничные дефекты, path traversal и декларативный характер валидатора, оформлен дефект [F-004](../../findings/F-004.md))

## Ожидаемое поведение

1. Функция `validate_context_budget` и сборщик контекста надежно обрабатывают граничные условия: пропущенные файлы, битые кодировки, дубликаты путей, аномально длинные строки без пробелов.
2. Проверка спецификаций и контекстных путей (`validate_spec_ref`) предотвращает выход за пределы репозитория (Path Traversal, `../`).
3. Механизм контекстных ограничений контролирует реальные обращения агента к файловой системе, а не только статически заявленные ссылки.

## Наблюдаемое поведение

1. **Path Traversal в ссылках спецификации**:
   - В `validate_spec_ref` путь резолвится через `(repo_root / file_part).resolve()`, но отсутствует валидация `relative_to(repo_root)`.
   - Путь вида `../outside_spec.md` при наличии файла на диске возвращает валидный статус (`None`), позволяя выходить за пределы репозитория.
2. **Тихий пропуск отсутствующих файлов**:
   - В `estimate_files_tokens` условие `if f.is_file()` молча пропускает несуществующие файлы, занижая расчёт токенов до 0 и не сообщая о битых ссылках в бюджетном линтере.
3. **Двойной учёт дубликатов**:
   - Повторяющиеся ссылки в `spec_refs` суммируют токены одного и того же файла несколько раз, провоцируя ложные срабатывания лимита `max_tokens`.
4. **Аномалия "Huge Line"**:
   - Файл из 100,000 непрерывных символов без пробелов (base64, minified blob) оценивается `len(words)=1` всего в **2 токена**.
5. **Декларативный контроль vs Реальные чтения**:
   - Подтверждено, что ни CLI `lint-context`, ни `validate_change_package` не осуществляют песочницу или перехват реальных чтений агента в рантайме; проверяются только ссылки, задекларированные во фронтматтере.
6. **Оформление дефекта**:
   - Все 5 уязвимостей и сценариев зафиксированы в [F-004](../../findings/F-004.md).
