**Verdict: `pass` для условий карточки.** На ревизии `60ea40438b0142797848356c660ab88286565e7d` (рабочий HEAD `c5ce48650ceb5b5780e0ee70a2a1bfc7b5536670`) выполнена детальная сверка контракта пятой фазы жизненного цикла — **Target** — по сквозной цепочке «инвариант -> документация -> навык агента -> схема/шаблон -> runtime gate FSM -> юнит/мутационный тест».

Результаты сопоставления зафиксированы в разделе 8 матрицы [backlog/matrices/contracts.md](../../../matrices/contracts.md).

## Подтверждённые инварианты фазы Target

1. **TAR-01 (Обязательность Red Evidence и ненулевой exit code, T2):** FSM валидирует (`fsm.py:330-338`), что свидетельство фазы red содержит ненулевой код возврата (`exit_code != 0`), а статус результата равен строго `expected-failure` (или `not-reproduced` при невозможности воспроизведения бага). Попытка пропустить «зелёный» результат теста или нулевой exit code гарантированно отсекается мутационным тестом T2 (`test_mutation_t2_red_evidence_with_passed_result_rejected`).
2. **TAR-02 (Физическая изоляция фаз evidence, T1):** Схема и FSM жестко требуют соответствия подкаталога типу фазы: файл, находящийся в `evidence/red/`, обязан иметь поле `phase: red`. Подделка фазы ловится мутационным тестом T1 (`test_mutation_t1_green_evidence_in_red_folder_rejected`).
3. **TAR-03 (Ссылка на существующую задачу, T4):** Каждое свидетельство обязано явно указывать поле `task: TASK-*`, и этот идентификатор обязан существовать в каталоге `tasks/` Change. Фантомные задачи бракуются мутационным тестом T4 (`test_mutation_t4_evidence_for_nonexistent_task_rejected`).
4. **TAR-04 (Присутствие Red Evidence в гейте targeting):** Функция `check_gate(..., "targeting")` физически проверяет наличие валидного yaml-файла в `evidence/red/`.
5. **TAR-05 (Допустимые переходы FSM):** Из состояния `targeting` разрешён переход только в `target-confirmed` или терминальный `not-reproduced`. Из `target-confirmed` возможен переход только в `implementing`.

## Наблюдения и ограничения

- **Семантика Red как доказательства:** В DeltaFuse Red является формализованным артефактом схемы `evidence.schema.yaml` с обязательной фиксацией команды, категории сбоя (`behavioral-mismatch`) и неизменности спецификации (`spec_status: unchanged`).
- **Обнаруженный разрыв (TAR-06):** Запрет на чтение и модификацию кода реализации на фазе Target задекларирован в документации (`docs/workflow.md:202`) и в инструкции агента (`target-task/SKILL.md:16`), но рантаймом фреймворка не перехватывается (зафиксировано в [F-002](../../findings/F-002.md)).
