# q6: корень `dir/*` — владение файлами, лежащими прямо в каталоге

**Состояние: принято и реализовано в 3.3.6** (`dir/*`; файловый корень и корень `*`
не делались, см. «Открытые вопросы» — вопрос 1 закрыт как «`dir/*` как есть», вопрос 3
— версия 3.3.6, вопрос 2 не решался и `*` не поддержан). Ниже текст исходного
предложения. Записано 2026-09-30 по итогам пилота Fuse-Back на
Python-Markdown. В разговоре о Fuse-Back оно проходило как «D8» (номер условный: в
требованиях Fuse-Back такого решения ещё нет, а в
`night-2026-09-21/DECISIONS.md` есть несвязанная запись D8).

Тип работы: изменение ядра DeltaFuse, отдельный PR. Той же природы, что два
правила каталога, реализованные в `0ada17a` (непересекающиеся `code_roots` у
`active`; остановка на `analyzed` для черновика с унаследованным кодом).

## Проблема

`code_roots` — только префиксы каталогов. `ownership._root_prefix` превращает
любой корень в `dir/` (`src/ratelimit`, `src/ratelimit/`, `src/ratelimit/**` →
`src/ratelimit/`), а `owners()` проверяет `rel.startswith(prefix)`. Корень,
названный файлом (`pkg/a.py`), даёт `pkg/a.py/` и не владеет ничем.

Следствие: **файлы, лежащие прямо в каталоге, нельзя отдать отдельно от его
подкаталогов.** Пока каталог целиком принадлежит одной capability, это не
мешает. Но как только его подкаталоги нужны другой capability, собственные
файлы каталога остаются ничьими.

Пилот Fuse-Back на Python-Markdown (33 файла в `markdown/`, из них 14 прямо в
каталоге, 19 в `markdown/extensions/`): Fuse-Back дробит каталог, расширения
получают capability, а 13 файлов ядра (`core.py`, `blockprocessors.py`,
`inlinepatterns.py`, `util.py`…), то есть сам продукт, остаются без владельца
(14-й, `test_tools.py`, исключён как тестовый).
Без владельца их нельзя ни характеризовать, ни маршрутизировать: `under_routing`
кладёт их в `unowned` («catalog gap, recorded, never judged»).

То же будет на JVM: в пакете `com/acme/billing/` классы лежат рядом с
подпакетами, а в Kotlin одна декларация `package` не обязана совпадать с
каталогом. Это уже отмечено как риск в Fuse-Back (`TIER2-CARDS.md` §5, пункт 2).

## Предложение

Новый вид корня: **`dir/*` — файлы, лежащие прямо в `dir`, без подкаталогов.**

| корень | владеет |
| --- | --- |
| `dir`, `dir/`, `dir/**` | всё дерево под `dir/` (как сейчас) |
| `dir/*` | только файлы, чей родительский каталог ровно `dir` |
| `*` | только файлы в корне репозитория (необязательно, см. ниже) |

Пример для Markdown:

```yaml
core:
  code_roots: [markdown/*]
extensions:
  code_roots: [markdown/extensions/]
```

Сегодня `dir/*` нормализуется в `dir/*/` и не совпадает ни с одним путём, то
есть корень такого вида — пустая операция. Поэтому расширение обратно
совместимо: существующие каталоги не меняют смысл.

### Сопоставление

`owns(root, rel)`:

- рекурсивный корень `P/`: `rel.startswith(P)`;
- прямой корень `D/*`: `rel.startswith(D + "/")` и в остатке нет `/`.

Хранить в том же `dict[str, list[str]]`: прямой корень как строка `D/*`
(признак — суффикс `/*`), рекурсивный как `P/`. Тип результата
`capability_code_roots()` не меняется.

### Непересечение (правило (a), `validate_active_code_roots`)

| пара | пересекаются, если |
| --- | --- |
| рекурсивный `P/` и рекурсивный `Q/` | один префикс начинается с другого (как сейчас) |
| прямой `D/*` и рекурсивный `P/` | `D + "/"` начинается с `P` (то есть `P` — сам `D` или его предок) |
| прямой `D/*` и прямой `E/*` | `D == E` |

`markdown/*` и `markdown/extensions/` не пересекаются; `markdown/*` и `markdown/`
пересекаются; `markdown/*` и `markdown/*` пересекаются. Сообщение об ошибке
остаётся прежним, в него подставляются исходные строки корней.

## Где менять

1. `src/deltafuse/core/ownership.py`: `_root_prefix` (сохранить `dir/*`),
   `owners()` (ветка для прямого корня). Общая функция сопоставления и
   пересечения в этом модуле, чтобы остальное её вызывало, а не дублировало.
2. `src/deltafuse/core/config.py`: `validate_active_code_roots` использует
   общую функцию пересечения вместо `startswith` в двух направлениях.
3. `src/deltafuse/core/fsm.py`: `_uncharacterized_draft_errors` строит путь
   как `repo_root / prefix.rstrip("/")` и обходит `rglob("*")`. Для `dir/*`
   такого каталога нет, правило D7 не сработает. Для прямого корня проверять
   только непосредственные файлы `dir`.
4. `docs/context-model.md` (и `.ru`): один абзац про `dir/*` в описании
   `code_roots`. Схема `capability.schema.yaml` не меняется: `code_roots` там
   `array` из `string`, без шаблона.
5. `CHANGELOG.md`: запись под следующей версией.

Не затрагивается: `workflow.code_roots` в `config.yaml` (глобы области записи
Worker'а, `src/**`) — отдельный ключ с другой семантикой; `test_roots`.

## Критерий приёмки

В `tests/unit/test_catalog_rules.py` (или соседнем файле) проходят:

- `dir/*` владеет `dir/a.py` и не владеет `dir/sub/b.py`;
- `markdown/*` + `markdown/extensions/` у двух `active` capability проходят
  `validate_config`; `markdown/*` + `markdown/` и два одинаковых `markdown/*`
  отвергаются;
- при `baseline: accepted` черновик с корнем `dir/*`, в котором есть файл,
  останавливает Change на `analyzed`; черновик с `dir/*` над пустым каталогом
  (proposal q8) не останавливает;
- `under_routing`: файл в `dir/` попадает в `unrouted`/`covered` по владельцу
  `dir/*`, файл в `dir/sub/` не попадает в него;
- полный набор тестов DeltaFuse зелёный.

## Что меняется в Fuse-Back после принятия

Это не часть PR в `deltafuse`, только чтобы оценить связность:

- `catalog/groups.py`: прямые файлы разбитого каталога получают группу с корнем
  `dir/*` вместо «ничьи: direct file of split directory»;
- `catalog/assemble.py`, `characterize/entrypoints.py` (`owned_files`),
  `characterize/preflight.py`: тот же смысл `dir/*` и то же правило
  непересечения;
- **защита от старой версии DeltaFuse.** Версия без этого изменения молча
  принимает `dir/*` как пустую операцию, и файлы остаются ничьими, но проверки
  проходят. Handoff должен проверять версию DeltaFuse и отказывать, а не
  пропускать.

## Что рассмотрено и не предлагается

- **Файл как корень** (`pkg/a.py`, точное совпадение). Нужен только когда
  внутри одного каталога надо разделить файлы между capability. Для JVM это
  тысячи однофайловых capability, а для дробления «прямые файлы каталога» они
  не нужны. Можно добавить позже тем же механизмом (`owns` по точному пути).
- **Вложенные корни с приоритетом самого длинного префикса** (`markdown/` —
  ядро, `markdown/extensions/` — расширения, файл принадлежит самому
  специфичному). Общее решение, но меняет `owners()` (возвращает одного
  владельца вместо множества) и смысл правила (a): вложенность пришлось бы
  разрешить. `dir/*` решает тот же случай без смены модели.
- **Общие глобы** (`dir/**/*.java`, `*.kt`). Другая по масштабу задача, вне
  этого предложения.

## Открытые вопросы владельцу

1. Принять `dir/*` как есть, или хочется файловый корень сразу?
2. Нужен ли корень `*` (файлы в корне репозитория), или достаточно `dir/*` для
   каталогов? В Python-проектах модули корня (`setup.py`, `conftest.py`) обычно
   не характеризуются, для JVM это не нужно.
3. Версия: как считать это изменение (расширение формата каталога) относительно
   `3.3.5`/следующей.
