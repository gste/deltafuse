# Изолированные прогоны

Решение владельца 2026-09-22. Квалификационные кампании уходят в изолированную
корпоративную среду: там тот же референсный Worker (`qwen3.8-27b` dense) за
сырым API, совместимым с OpenAI, цена прогона для владельца — $0, PyPI доступен,
на вынос результатов ограничений нет, политика компании это разрешает.

Дома остаются сборка пакета, оценка скрытыми наборами, анализ и починка
фреймворка. В изолированной среде — только прогон под супервизором.

```
дом: пакет (коммиты закреплены) ──► среда: кампания под супервизором
      ▲                                         │
      └── дом: оценка T1 скрытыми наборами ◄── бандл: трассы, песочницы, инциденты
```

## Принципы

1. **Супервизор заменяет механику, а не ремонт.** Зависания, ретраи, петли,
   незавершённые шаги — его. Правка фреймворка или песочницы посреди прогона —
   никогда: прогон перестал бы соответствовать закреплённому коммиту, а помощь
   сильной модели незаметно подменила бы слабого Worker'а.
2. **Каждое вмешательство — метрика.** Инциденты пишутся в журнал прогона и
   считаются (`supervisor_interventions`, наблюдаемый порог). Прогон, дошедший
   до `converged` с подсказками, не равен чистому.
3. **Скрытые наборы не уезжают.** Пакет несёт публичную часть кейсов (seed,
   `case.yaml`, `input.md`, `WORKER.md`); `hidden_suite/`, `oracle*`,
   `mutations/` остаются дома. В среде кампания идёт с отложенной оценкой;
   T1 и process-оценка считаются дома по возвращённым песочницам.
4. **Слой управления детерминирован.** LLM-триаж (сильная модель, закрытое меню
   действий, только запись инцидента) — опционально и позже, после того как
   детерминированный слой покажет, каких инцидентов больше.
5. **Ремонт — дома, между кампаниями.** Перед отправкой пакета обязательны
   Core-only прогоны жизненного цикла (`tests/e2e/test_core_lifecycle.py`): один
   тупик ядра иначе стоит целой пересылки. Первая волна в среде — диагностическая.

## Работы (в `deltafuse-bench`, раннер `qualify/qualify.py`)

| # | работа | состояние |
| - | ------ | --------- |
| I1 | Endpoint: `--endpoint`, `--api-key-env`, `--served-model` (имя у провайдера) отдельно от `--model` (идентичность для порогов и токенайзера); стоимость неизвестна → потолок по вызовам/токенам; сетевые сбои ретраятся | — |
| I2 | Отложенная оценка: `--defer-score` в среде, `rescore <кампания> --pack <полный>` дома; метрики T2–T10 считаются в среде, T1 — дома | — |
| I3 | Супервизор: лимит времени шага, «нет прогресса», петля гейта, незавершённый шаг → одна повторная подсказка, возобновление кампании, heartbeat, `incidents.jsonl`, метрика `supervisor_interventions` | — |
| I4 | Пакет: `qualify/iso.py pack` — исходники обоих репозиториев на закреплённых коммитах без скрытых частей, токенайзер, манифест с хэшами, скрипт запуска, офлайн-preflight | — |
| I5 | Бандл: `iso.py bundle` в среде (кампания, песочницы с `.git`, трассы) и `iso.py import` дома → `rescore` | — |
| I6 | LLM-триаж инцидентов | отложено (принцип 4) |

Порядок: I1 → I2 → I3 → I4/I5. После I5 — одна диагностическая кампания, затем
проверка сразу всех реализованных пунктов роадмапа (решение владельца: q4 и
остальные проверяются одним прогоном, а не по отдельности).
