# Изолированные прогоны

Решение владельца 2026-09-22. Квалификационные кампании уходят в изолированную
корпоративную среду: там тот же референсный Worker (`qwen3.8-27b` dense) за
сырым API, совместимым с OpenAI, цена прогона для владельца — $0, PyPI доступен,
на вынос результатов ограничений нет, политика компании это разрешает.

Дома остаются сборка пакета, оценка скрытыми наборами, анализ и починка
фреймворка. В изолированной среде — только прогон под супервизором.

```
дом: пакет (коммиты закреплены) ──► среда: кампания под супервизором
      ▲                                         │
      └── дом: оценка T1 скрытыми наборами ◄── бандл: трассы, песочницы, инциденты
```

## Принципы

1. **Супервизор заменяет механику, а не ремонт.** Зависания, ретраи, петли,
   незавершённые шаги — его. Правка фреймворка или песочницы посреди прогона —
   никогда: прогон перестал бы соответствовать закреплённому коммиту, а помощь
   сильной модели незаметно подменила бы слабого Worker'а.
2. **Каждое вмешательство — метрика.** Инциденты пишутся в журнал прогона и
   считаются (`supervisor_interventions`, наблюдаемый порог). Прогон, дошедший
   до `converged` с подсказками, не равен чистому.
3. **Скрытые наборы не уезжают.** Пакет несёт публичную часть кейсов (seed,
   `case.yaml`, `input.md`, `WORKER.md`); `hidden_suite/`, `oracle*`,
   `mutations/` остаются дома. В среде кампания идёт с отложенной оценкой;
   T1 и process-оценка считаются дома по возвращённым песочницам.
4. **Слой управления детерминирован.** LLM-триаж (сильная модель, закрытое меню
   действий, только запись инцидента) — опционально и позже, после того как
   детерминированный слой покажет, каких инцидентов больше.
5. **Ремонт — дома, между кампаниями.** Перед отправкой пакета обязательны
   Core-only прогоны жизненного цикла (`tests/e2e/test_core_lifecycle.py`): один
   тупик ядра иначе стоит целой пересылки. Первая волна в среде — диагностическая.

**Смоук 2026-09-22** — весь цикл на заглушке OpenAI-совместимого сервера, $0:
пакет 16 МБ → `run.ps1` (venv, PyPI, токенайзер) → прогон M01 → бандл 117 КБ →
импорт дома → скрытые проверки. Нашёл два дефекта, оба исправлены (`03e383f`):
файлы из архива с датой 1970 ломали zip; детектор «нет прогресса» не видел
простоя, потому что ядро пишет журнал в `.deltafuse/` на каждом шаге (79
одинаковых шагов подряд).

**Решения, принятые мной (владелец может пересмотреть):** шаг 45 мин; 3 шага без
изменений; 6 одинаковых выборов подряд; прогон по умолчанию 120 мин в `iso.py
run`; кампания в среде по умолчанию диагностическая (`--qualifying` — явно);
повторная подсказка модели не добавлена — повтор шага идёт с тем же брифом,
чтобы супервизор не помогал модели содержанием.

## Как запускать

Дома (оба репозитория закоммичены):

```
python qualify/iso.py pack --out D:/iso/pack-1 --cases M01-cooldown M02-policy-stats M03-adversarial
```

`--tokenizer` — если Python не видит `%LOCALAPPDATA%\deltafuse\tokenizers\Qwen_Qwen3.8-27B`
(Python из Microsoft Store перенаправляет `AppData\Local`).

В среде (скопировать папку целиком):

```
run.ps1 --endpoint http://<host>:<port>/v1/chat/completions --served-model <имя модели у провайдера> --model <идентичность для порогов> [--ask-key | --api-key-env ИМЯ] [--repeats 3] [--campaign-id X]
```

Ключ: `--ask-key` спрашивает его скрытым вводом и передаёт раннеру через
переменную окружения — в историю оболочки и в командную строку он не попадает.
`--api-key-env` принимает **имя** переменной, а не сам ключ.

Медленный или ограниченный квотой эндпоинт: `--request-timeout` (по умолчанию
120 с), `--max-retries`, `--max-step-calls` (по умолчанию 24),
`--max-run-minutes`. Время, проведённое в ожидании после отказов, попадает в
отчёт как `provider_wait_s` — без него «медленная модель» и «жёсткая квота»
неотличимы.

Прервалось — тот же `--campaign-id`: готовые прогоны сохраняются. Результат —
`results-<campaign>.zip` рядом с `run.ps1`.

Дома:

```
python qualify/iso.py import D:/iso/pack-1/results-<campaign>.zip
```

Импорт судит фреймворком того коммита, что записан в `PACK.json` (временный
worktree, если домашняя копия на другом коммите), и печатает, каким коммитом
бенча он судил. Пересудить текущим кодом — только явно, `--judge-with-current`.

Порядок дальше: одна диагностическая кампания в среде, затем проверка сразу всех
реализованных пунктов роадмапа (решение владельца: q4 и остальные — одним
прогоном).
