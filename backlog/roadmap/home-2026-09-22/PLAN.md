## Решения по ходу (мои; владелец может пересмотреть)

- **Интерфейс Writer'а для Worker'а.** Ядро даёт одну команду `deltafuse
  artifact write --kind K --change DIR --input FILE.json`: нет файла — создать,
  есть — обновить перечисленные поля; ожидаемый sha256 ядро берёт само под
  блокировкой. Вход — `{"identity"|"target", "fields": {...}, "body": "..."}`.
  Хост с вызовом функций отдаёт это модели как типизированный инструмент (JSON
  в аргументах инструмента — родной формат модели), хост только с shell — как
  файл JSON. Отдельные `create`/`update` остаются для точного контроля.
- **Ошибка Writer'а — ответ инструмента, а не гейт.** Неверное поле отвергается
  до записи с точным сообщением; модель чинит в том же шаге, T3 не растёт.

## H1 — итог

- `deltafuse artifact write` + значения ядра (бюджет задачи, индекс `change.yaml`,
  слияние списков `spec-delta` по слайсам); `route` в дескрипторах routing и change.
- Intake скаффолдит через `deltafuse new`; analyze, specify, decompose пишут через
  Writer; примеры в skills проверяются настоящим Writer'ом.
- Leash: структурный файл проходит, только если его байты дал Writer, `deltafuse
  state` (теперь пишет sha256 в receipt) или `decide`.
- E2E `tests/e2e/test_writer_lifecycle.py`: intake → declare путём воркера, leash
  после каждого шага — зелёный с первого раза.
- **Остаток:** записи Decision (`docs/decisions/**`) модель пишет сама — Writer
  резолвит путь от каталога Change, а Decision живёт в корне; редкий случай в
  текущих кейсах. Skill `analyze` вырос с 786 до 947 слов (две формулы Writer'а).
