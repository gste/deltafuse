## 1. Summary of Changes

Remediated Review Finding 5 where identical update retries failed with `stale_target` before receipt lookup, and where reusing a request ID in `create` with a changed body returned the old receipt.

### Key Modifications:
- `src/deltafuse/core/artifact_transactions.py`:
  - Added `get_receipt(transaction_id)` to load and return existing durable receipts from `.deltafuse/receipts/`.
  - Added `find_transaction_by_request_id(request_id)` to inspect `.deltafuse/journal/` for prior transactions under `request_id`.
- `src/deltafuse/core/artifacts.py`:
  - Bound request identity hashing (`raw_req_bytes` / `raw_req_hash`) to every behavior-affecting field: `operation`, `kind`, `identity`/`target`, `semantic_payload`/`patch`, `body`/`body_replacement`, `expected_sha256`, `canonicalize_metadata`, and `auth_context`.
  - Moved committed transaction lookup under `ProductMutationLock` BEFORE performing `validate_expected_hash` in `update`.
  - Identical update retries recognize the committed transaction and return its durable receipt without failing `stale_target` or rewriting target files.
  - Reusing a `request_id` with any changed request parameter (e.g. `body` in `create`, or `patch`/`expected_sha256` in `update`) raises `ArtifactTransactionError` with `code="idempotency_conflict"`.
- `tests/unit/test_artifact_service.py`:
  - Added Red reproduction test `test_reproduce_finding_5_update_idempotency_and_create_body_conflict`.
  - Added tests for update retries with unrelated later target edits (`test_update_retry_with_unrelated_later_target_edit`) ensuring historical receipts return without overwriting live file edits.
  - Added no-op update retry and conflict check tests (`test_noop_update_retry_and_conflict_checks`).
- `tests/integration/test_artifact_cli.py`:
  - Added subprocess CLI test `test_subprocess_artifact_update_retry_and_idempotency` verifying CLI retries and idempotency.
