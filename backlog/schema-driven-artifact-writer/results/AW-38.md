## 1. Summary of Changes

Remediated Review Finding 4 where a product lock retaining `framework.source` but omitting `framework.content_hash` allowed artifact creation because content_hash comparison was conditional on a non-empty string.

### Key Modifications:

1. `src/deltafuse/core/artifact_registry.py`:
   - Updated `verify_product_lock` to strictly require all three framework pin fields: `version`, `source`, and `content_hash`.
   - Added explicit format checking for `content_hash` (`^sha256:[a-fA-F0-9]{64}$`).
   - Ensured that missing, empty, null, or malformed `content_hash` or unavailable executing framework asset identity fails closed with `ArtifactRegistryError` and is never skipped.

2. `src/deltafuse/cli.py`:
   - Updated `artifact update` CLI handler to use robust `cid` (Change ID) resolution matching `artifact create`, ensuring consistent policy context resolution.

3. `tests/unit/test_artifact_registry.py`:
   - Added `test_aw38_verify_product_lock_rejects_missing_and_malformed_fields` testing independent rejection of missing `version`, `source`, `content_hash`, malformed `content_hash` string, and empty executing asset identity.

4. `tests/integration/test_artifact_cli.py`:
   - Added `test_aw38_cli_create_missing_content_hash_rejected` asserting exit code 5 (`Artifact assets unavailable`) and unchanged disk state when `framework.content_hash` is omitted from `.deltafuse/lock.yaml`.

5. `tests/unit/test_artifact_service.py`:
   - Updated test repo fixtures to include valid `change.yaml` for Change authority validation.
