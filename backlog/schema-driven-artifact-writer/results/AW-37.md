## Red, implementation, Green

- Exact counterexample, unchanged expectation and pre-edit source identity:
  - Counterexample: `change.yaml` containing only `status: normalized` (or `id: null`, `id: ""`, `change: CHG-905`) allowed CLI `artifact create` with exit 0, creating tasks without valid Change identity.
  - Pre-edit source: `resolve_change_stage` only compared `file_cid != change_id` when `file_cid` was truthy (`if file_cid and file_cid != change_id:`), allowing missing/null/empty ID to fall through to `status: normalized` and return valid active stage.
- Exact Red argv/input, exit, assertion:
  - `python -c 'from deltafuse.core.artifact_policy import resolve_change_stage; ... (d / "change.yaml").write_text("status: normalized\n"); print(resolve_change_stage(p, "CHG-905"))'` returned `normalized` (exit 0).
  - `main(["artifact", "create", "--kind", "task", "--change", str(chg), ...])` with `change.yaml` containing only `status: normalized` returned exit code 0 and created task file `TASK-001.md`.
- Minimal production change and why it enforces the invariant:
  - In `src/deltafuse/core/artifact_policy.py` (`resolve_change_stage`): Strictly required `change_id` and `data.get("id")` to exist, be strings matching `^CHG-[0-9]{3,}(-[a-z0-9-]+)?$`, and equal each other. Removed alternate-field fallback (`data.get("change")`). Non-string status or invalid/missing ID immediately returns `"missing_change_authority"`.
  - In `src/deltafuse/cli.py` (`cmd_artifact_create`, `cmd_artifact_update`): Added strict `id` validation on `change.yaml` when present in the specified directory, returning exit 3 (`missing_change_authority`) on missing, null, empty, wrong-type, or mismatched Change ID.
- Exact Green argv/input, exit, assertion:
  - `resolve_change_stage(p, "CHG-905")` on `status: normalized` returns `missing_change_authority`.
  - `main(["artifact", "create", ...])` returns exit code 3 (`missing_change_authority`) and creates no task file.
- Nearby adversarial controls and legitimate-operation regression:
  - Tested `id: null`, `id: ""`, `id: 123`, `id: ['CHG-905']`, `change: CHG-905`, `id: CHG-999`, and `id: CHG-905` (valid). All invalid variants reject; valid variant succeeds.
