## Implementation and explicit scope adjustments

1. `src/deltafuse/core/artifacts.py`:
   - Removed first-file slice inference logic (`glob("SLICE-*.md")`) in `ArtifactService.create` for `kind="task"`.
   - Required explicit slice ownership: either `"slice": "SLICE-XX"` in `semantic_payload` or `auth_context.work_item == "SLICE-XX"`.
   - Validated that if both `semantic_payload["slice"]` and `auth_context.work_item` are provided and `auth_context.work_item` matches `SLICE-*`, they must be identical (otherwise raising `ArtifactPolicyError` with `code="policy_denied"`).

2. `src/deltafuse/core/artifact_registry.py`:
   - Enforced root containment in `_find_file` helper for referenced files (`cand.resolve().relative_to(check_base)`).
   - Updated `_find_file` to capture frontmatter/YAML parsing errors without swallowing them.
   - Updated `validate_references` for `slice` references in tasks, `depends_on` dependencies, `spec_refs`, and `design_ref`:
     - Verified referenced file exists and is strictly parsable (reports `missing_reference` diagnostic if malformed YAML/frontmatter).
     - Verified referenced file contains expected identity (`id` field matches `slice_id` or `dep_id`).
     - Verified referenced file belongs to expected owning Change (`change` field matches `cid` / `change_id`).

3. `tests/unit/test_artifact_service.py` & `tests/unit/test_artifact_registry.py`:
   - Added Red/Green unit test `test_aw34_missing_slice_selection_and_malformed_slice_rejection` in `test_artifact_service.py`.
   - Added unit test `test_aw34_validate_references_strict_parsing_and_change_boundary` in `test_artifact_registry.py`.

4. Test fixtures & compatibility:
   - Strengthened test fixtures in `tests/e2e/test_artifact_workflow.py`, `tests/integration/test_artifact_compatibility.py`, and `tests/fixtures/change_builder.py` to supply explicit slice ownership and matching Change IDs.
