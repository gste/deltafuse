## 1. Executive Summary

Card AW-11 implemented CLI subcommands under `deltafuse artifact` (`describe`, `create`, `update`, `validate`) and tool-call argument schema exports in `src/deltafuse/cli.py`, with unit test suite `tests/unit/test_artifact_cli.py` and integration test suite `tests/integration/test_artifact_cli.py`.

It exposes:
1. `deltafuse artifact describe`: Returns allowed semantic fields and Core-owned fields, or exports tool-call argument schemas (`--export-schema`).
2. `deltafuse artifact create`: Reads JSON input from a file or stdin (`--input -`), enforces authorization policy, rejects Core-owned fields (`status`, `schema_version`, `framework`), creates artifacts atomically, and outputs structured receipts or text.
3. `deltafuse artifact update`: Reads JSON patches from a file or stdin, checks `expected_sha256`, applies JSON Pointer updates, and writes atomic replacements.
4. `deltafuse artifact validate`: Read-only storage and policy validation returning exit 0 (valid) or 2 (invalid).
5. Documented Exit Codes: 0 (success/valid), 2 (invalid input/schema/syntax), 3 (authorization/Core-owned field denied), 4 (stale target/identity conflict), 5 (persistence/transaction failure).
6. Tool argument schema exporter `export_tool_schemas()` excluding Core-owned fields from public worker write envelopes.
