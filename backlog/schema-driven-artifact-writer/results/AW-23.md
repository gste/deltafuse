## 1. Summary of Changes

Remediated Review Finding 3 where `deltafuse artifact create` accepted duplicate JSON keys and an unknown top-level envelope field, returned exit 0, and committed an artifact to disk using standard `json.loads`.

- `src/deltafuse/core/artifact_reader.py`:
  - Added `strict_parse_json` function enforcing byte bounds prior to reading/decoding, UTF-8 surrogate check, duplicate key rejection at every depth level, non-finite number rejection (`NaN`, `Infinity`), nesting depth bounds (`max_depth=100`), and JSON object type enforcement.

  - Added `body_replacement` to allowed properties in the closed request envelope contract.

  - Added `get_envelope_schema` and `validate_operation_envelope` for structured validation of request envelopes against `artifact-writer.schema.yaml`.
- `src/deltafuse/core/artifacts.py`:
  - Added `request_id` (`^[a-zA-Z0-9_\-]+$`) and `expected_sha256` pattern validation to `create` and `update` service methods.
- `src/deltafuse/cli.py`:
  - Wired bounded reading, strict JSON parsing (`strict_parse_json`), closed operation envelope validation (`validate_operation_envelope`), explicit empty body replacement preservation (`""`), and exit code mappings (2 for parse/envelope error, 3 for policy/core-owned field, 4 for lock/hash/conflict, 5 for unexpected error) into `artifact create` and `artifact update` CLI subcommands with `--json` error diagnostic output.
- `tests/unit/test_artifact_cli.py` & `tests/unit/test_artifact_reader.py`:
  - Added Red test `test_reproduce_finding_3_cli_create_duplicate_key_and_unknown_envelope_field_rejected`, unit tests for `strict_parse_json`, and integration tests for explicit empty body replacement.
