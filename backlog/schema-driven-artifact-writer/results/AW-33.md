## Implementation and explicit scope adjustments

1. `src/deltafuse/core/artifact_storage.py`:
   - Added `verify_published_target_readback(target_path, expected_sha256)` helper to verify that a published target file exists on disk and its SHA256 digest matches expected output bytes.

2. `src/deltafuse/core/artifacts.py`:
   - Added `verify_published_artifact(target_path, expected_sha256, kind, registry, product_root, change_dir, change_id)` helper.
   - Enforced readback verification (target existence, expected hash digest match, strict frontmatter parsing, and storage schema validation) after atomic publication (`atomic_create` / `atomic_replace`) and before receipt finalization (`finalize_receipt`).
   - Added readback error handling in `create` and `update` (including no-op update check), updating transaction journal state to `readback_failed` and raising `ArtifactTransactionError(code="readback_verification_failed")` if target readback verification fails.

3. `src/deltafuse/core/artifact_transactions.py`:
   - Added `mark_readback_failed(transaction_id, error_message)` method on `TransactionManager`.
   - Updated `recover_pending_transactions` to run `verify_published_artifact` on target readback before finalizing a `committed` receipt during recovery. If readback verification fails (e.g. corrupted target bytes or missing file), recovery marks state `ambiguous_stopped` without overwriting target files or issuing false committed receipts.

4. `tests/integration/test_artifact_crash_recovery.py`:
   - Added `test_aw33_post_publication_target_corruption_causes_operation_failure` (create with fault-injected target corruption).
   - Added `test_aw33_update_post_publication_target_corruption_causes_operation_failure` (update with fault-injected target corruption).
   - Added `test_aw33_post_publication_missing_target_causes_operation_failure` (create with fault-injected unlinked target).
   - Added `test_aw33_recovery_verify_published_readback_handling` (recovery verification of corrupted published targets).

## Scope of the result and remaining limits

- **Recovery safety:** `recover_pending_transactions` does not issue committed receipts for corrupt or missing files, marking state `ambiguous_stopped` without overwriting unrelated content.
- **Slice ownership & reference validation:** Explicit slice ownership and reference identity validation remain AW-34.
