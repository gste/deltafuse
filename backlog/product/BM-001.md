# BM-001 — Агент-агностичный сквозной бенчмарк (M01)

- **Дата:** 2026-09-10
- **Статус:** `done` — `feature/2026-09-10-worker-bench`
- **Слой:** CLI (`deltafuse bench`), кейс `process/bench/cases/M01-cooldown`
- **Зависимости:** 2.3.0. Не WA-001. Не вызов LLM из ядра.

`deltafuse eval --provider mock` дампит пакет за один ход. A09 привязан к ornith `files[]`. Cursor + облако нечем честно сравнить: нет общего продукта, скрытого оракула и score после каждого шага.

## Зачем

Один и тот же Change (cool-down penalty на существующем limiter) прогоняется любым воркером: Cursor+Opus, Gemini Flash, человек, будущий свой агент. Ядро только готовит дерево и **считает диск**. Модель в CLI не вызывается.

## Минимум

```text
deltafuse bench init M01-cooldown <product-dir>
# воркер работает в product-dir по skills / next
deltafuse bench score <product-dir> --stage specify --json
deltafuse bench score <product-dir> --json --label opus-5
deltafuse bench compare a.json b.json
```

- Init: installer + seed spec/code + intake. **Нет** `oracle.yaml` и hidden suite в продукте.
- Score по шагам: Intake → Analyze → Specify → Decompose → Declare → Implement → Verify.
- Headline `score` только с журналом retries; без него `n/a`. `M01` — пол, не рейтинг моделей.
- На шаге: `check-gate` + оракул (capability, live spec tokens, seed hash до Implement, hidden pytest по тестам только при score implement).
- Human Gate DEC на этом кейсе не ожидается; auto-accept не требуется и не выполняется scorе'ром.
- Сравнение моделей — два JSON score, не два промпта.
