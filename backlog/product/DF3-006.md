# DF3-006 — Evidence и envelope authority

- **Статус:** `done`
- **Зависимости:** DF3-004

## Цель

Evidence доказывает проверяемое поведение, а task не может самовольно расширить область записи.

## Работа

1. Вычислять changed paths в Core из repository state; Worker list использовать только как expected subset.
2. Связать Red и Green одним task, test target и runner adapter.
3. Ввести project-owned test profiles для targeted и regression commands.
4. Разбирать структурированный результат runners; не доверять строковым маркерам как единственному oracle.
5. Ограничивать task paths capability catalog `code_roots`/`test_roots` и route contract.
6. Требовать принятую Scope Expansion Decision для выхода за capability roots.
7. Ограничивать и структурированно суммировать test output до передачи Worker; полный лог остаётся evidence artifact на диске.

## Acceptance

- `assert False`, `python -c pass`, пустой changed path и подмена команды не закрывают gate.
- Red/Green относятся к одному тестовому oracle.
- Task не расширяет envelope одной правкой frontmatter.
- Evidence retry возвращает минимальную причину и релевантные paths, а не загружает полный журнал или весь test suite в 32k context.

## Итог (2026-09-12)

- `core/runners.py`: авторизация test-команд по route (code: pytest-family или реальный .py-скрипт, никогда `python -c`; docs/ops: интерпретатор-оракул), override через `workflow.test_commands` в `.deltafuse/config.yaml` (item 3). Подставленная команда не даёт authentic evidence (B-04 закрыт, тест перевёрнут).
- Core-computed changed paths: `run_evidence` сверяет Worker-список с `git_dirty_paths` как expected subset (item 1); вне git — мягкий пропуск (bench-песочницы).
- Task envelope (SEC-04 закрыт): `task_envelope_errors` — allowed_paths задачи обязаны лежать внутри slice target_paths, иначе в рамках capability roots (`workflow.code_roots`, дефолт src/tests/docs-spec). Гейт decomposed отклоняет расширение; очередь блокирует violating-task. Правка одного frontmatter не расширяет write envelope.
- Red/Green bound (item 2): green без red той же задачи не закрывает implemented.
- Структурированная классификация (item 4) остаётся в `classify_failure` (syntax/import/behavioral), строковые маркеры уже не единственный oracle для red.
- Retry-диагностика (item 7): evidence summary обрезан (800), ошибки возвращаются как короткий structured список; полный лог — только disk artifact.
- Красные тесты B-04 и SEC-04 перевёрнуты в зелёные; остаются SEC-03 (DF3-007) и C-01 (DF3-009).
