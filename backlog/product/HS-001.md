# HS-001 — Поверхность хоста, не ядра

- **Дата:** 2026-09-10
- **Статус:** `planned`
- **Слой:** `docs/contracts/**` в этом репозитории; реализация кнопок / UI — хост (Cursor, IDE, fuse-map), не Core
- **Зависимости:** нет. Ортогонально SK-001

Ядро уже отдаёт `next --json` с `halt.choices`, пишет клик через `deltafuse decide`, держит bench pack за `--pack` / `DELTAFUSE_BENCH_PACK` и не делает `git push`. Хост всё ещё может показать JSON воркеру вместо кнопок, положить pack в песочницу или нарисовать fuse-map внутри этого репозитория.

## Зачем

Through-mode (`/run`) бесполезен, если Human Gate — текст в чате, который модель «принимает» сама. Bench бесполезен, если воркер видит oracle. Merge — не шаг Worker.

Контракт хоста должен быть таким же жёстким, как схема Change: что хост **обязан** показать кнопками, чего **нельзя** класть на машину воркера, чего **нет** в этом репозитории.

## Что сделать здесь (канон)

- Зафиксировать `halt.choices` как host contract (`docs/contracts/**`): поля, `kind` (`decision` | `spec` | `done` | …), что клик идёт в `deltafuse decide`, что inspect ≠ accept.
- Явно: bench pack и scorecard не живут в sandbox и не ставятся адаптером skills; хост/judge держит pack снаружи.
- Явно: merge и `git push` — Human Gates; Core их не выполняет; `/run` на них останавливается.
- Явно: fuse-map UI читает `deltafuse board --json` из другого репозитория; этот репозиторий отдаёт снимок, не рисует доску.

## Не делать

- Кнопки, IDE-плагин, fuse-map UI в `src/deltafuse/**`.
- Auto-accept DEC / spec / merge.
- Класть oracle / hidden suite в product sandbox или в generated skills.
- Смешивать с SK-001 (форма YAML).

## Acceptance

В `docs/contracts/**` есть проверяемый контракт halt (поля `choices`, кто вызывает `decide`). Layout / installer / bench тесты подтверждают: pack не копируется в sandbox; адаптеры не содержат oracle. Канон одним абзацем говорит, что UI доски и кнопки хоста живут вне этого репозитория.
