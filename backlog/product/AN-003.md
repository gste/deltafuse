# AN-003 — Specify по одному срезу, live spec только в spec_refs

- **Дата:** 2026-09-10
- **Статус:** `done` — `feature/2026-09-10-worker-kernel`
- **Слой:** CLI (`next`), гейт `specified`, skill Specify
- **Зависимости:** [AN-001](AN-001.md). F-010 не снимается.

Holdout Specify сдыхал на одном сливе `spec-delta` без живых файлов (F-010) и на чтении всего `docs/spec/**`. Скилл уже говорит «один срез»; Ядро это не называло.

## Зачем

После Analyze ornith знает capability и `spec_refs`. Specify должен править только эти файлы постановки, затем следующий срез. Human Gate на spec — после всех срезов, как сейчас (`specification-proposed` / accept).

## Минимум

```text
deltafuse next --step specify --json
```

- `specify_pass: slice` + `slice_id` + `capability` + `spec_refs` + узкий `allowed_read` / `allowed_write`
- нет `docs/spec/**` в этом JSON; только файлы среза (и `_capabilities.yaml` при catalog delta)
- срез с `status: specified|decomposed|verified` пропускается
- все срезы specified, Change ещё `analyzed` → `specify_pass: close` (check-gate, не новый spec)
- bugfix по-прежнему skip Specify

Гейт `specified`: F-010 как было; плюс `added`/`modified` в `spec-delta.md` обязаны попадать в union `spec_refs` срезов (файл без якоря) или catalog spec этой capability. Чужой домен в spec-delta — fail.

Воркер не зовёт `check-gate specified` на середине набора срезов.

## Не делать

- Менять порядок Specify/Decompose
- Auto-accept spec Human Gate
- Писать постановку из Ядра
- Тюнить промпты A09
- Coverage invent (уже AN-002)

## Acceptance

- После Analyze: `next` → Specify `SLICE-01` и `spec_refs` этой capability
- Два среза: после `SLICE-01` status specified → `next` → `SLICE-02`
- spec-delta `added` на файл вне slice spec_refs → `specified` fail
- live spec + catalog по-прежнему нужны (F-010)
- `--json` не пишет дерево продукта
