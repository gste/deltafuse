# DF3-009 — Bench, документация и release qualification

- **Статус:** `blocked`
- **Зависимости:** DF3-005, DF3-008

## Цель

Доказать гарантии 3.0 на всех платформах и подтвердить, что reference 35B A3B Worker качественно проходит Process в полном окне 32k.

## Работа

1. Считать process score по уникальным последовательным transitions.
2. Добавить adversarial M03: gate spam, oracle leak, journal forgery, envelope escape, synthetic evidence.
3. Изолировать judge pack от Worker на уровне wheel/machine boundary.
4. Синхронизировать EN/RU; убрать захардкоженные количества тестов.
5. Добавить единый config validator для `project.baseline` и остальных config contracts.
6. Выпустить migration guide, compatibility table и rollback procedure.
7. Прогнать pytest, оба smoke tests, wheel smoke и layout validation на v2/v3 fixtures.
8. Выполнить по три независимых чистых прогона M01, M02 и adversarial M03 на `ornith-1.5-35b-a3b` через LM Studio с context limit 32768; cloud/mock fallback запрещён.
9. Для каждого прогона сохранить model/framework manifest, disk score, context peak, files loaded, stages/retries, hallucinated paths и envelope violations.
10. Сравнить M01/M02 с DF3-001 v2 baseline и применить заранее зафиксированные thresholds; не выбирать лучший прогон вместо полного набора.

## Acceptance

- Gate spam не повышает score.
- Windows и POSIX clean checkouts проходят одинаковый qualification suite.
- v2 migration и rollback проверены end-to-end.
- Нет legacy runtime paths вне документированного migration слоя.
- Каждый reference-model прогон помещается в 32k без молчаливого truncation обязательного контекста.
- Медианные correctness/process показатели достигают thresholds из DF3-001 и не регрессируют относительно v2 baseline на сопоставимых cases.
- Release report публикует все три результата каждого case и provenance, а не только лучший результат.
