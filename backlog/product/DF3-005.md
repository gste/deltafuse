# DF3-005 — Distribution, scaffolding и upgrade

- **Статус:** `done`
- **Зависимости:** DF3-003

## Цель

Одинаково работоспособная установка из nested checkout и wheel без потери provenance.

## Работа

1. На build генерировать immutable runtime bundle из schemas, skills и templates.
2. Читать wheel assets через `importlib.resources`; не копировать canonical docs в продукт.
3. Проверять bundle manifest при запуске и включать его в framework pin.
4. Добавить deterministic Change scaffolding; каркас не закрывает Intake.
5. Улучшить существующий `validate`, не добавлять второй validator command.
6. Блокировать update между несовместимыми v3 contract revisions при активных Changes до явного закрытия или переноса Change и повторного evidence run.

## Acceptance

- Wheel устанавливается в пустой venv и проходит CLI/smoke без source checkout.
- Source и wheel дают семантически одинаковые schemas/templates.
- Update не переподписывает evidence и не меняет product-owned files.

## Итог (2026-09-12)

- Runtime bundle: `scripts/sync_assets.py` копирует process/{schemas,templates,skills} в `src/deltafuse/assets/` и пишет manifest.json (SHA-256 на файл). Канонический источник остаётся в process/**, bundle — генерируемый контент.
- `deltafuse new <change-id> --route code|docs|ops`: детерминированный каркас Change (status normalized, без claims); Intake не закрывается (тест). Каркас детерминирован (кроме created) и отвергает коллизии/плохие id.
- Wheel: `deltafuse.assets` поставляется как package-data (`[tool.setuptools.package-data]`); installer в wheel-режиме берёт assets через `core/assets.py` (importlib.resources), версия из метаданных пакета, pin — SHA-256 от manifest.json.
- Bundle manifest верифицируется при использовании (tamper/missing = AssetError); schemas source и bundle byte-identical (тест).
- Fail-closed upgrade (C-02): изменение pin при активных Changes блокирует `install --force`; evidence никогда не переподписывается. Без активных Changes upgrade проходит.
- B-01 перевёрнут в зелёный (bundle-тест вместо file-content assertions); оставшиеся красные: B-04, SEC-03, SEC-04, C-01 (DF3-006/007/009).
- Docs: `docs/using.md` / `using.ru.md` дополнены заметкой о каналах установки, scaffolding и fail-closed upgrade.
