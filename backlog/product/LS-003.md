# LS-003 — Правка продукта в обход Change

- **Дата:** 2026-09-11
- **Статус:** `done` — orphan `src/**` / `tests/**` / `docs/spec/**` без покрывающего Change падает; docs-route не покрывает `src/**`
- **Слой:** тот же `deltafuse leash`, правила orphan-diff
- **Зависимости:** [LS-002](LS-002.md)

Фронтир в Composer не запускает `/run`. Envelope текущего шага пустой: selected может быть intake «нет файла» или `halt.kind: done`. Тогда LS-002 молчит, а `src/` и `docs/spec/**` уже изменены.

## Зачем

Это дыра, из-за которой DF не сильнее Spec Kit. Поводок должен ловить *отсутствие* процесса, не только выход за глоб шага.

## Что сделать

- Если в diff есть пути продукта (`src/**`, `tests/**`, `docs/spec/**`, опционально `docs/decisions/**` кроме шаблона) и нет Change, чей текущий шаг/envelope эти пути покрывает — отказ.
- Docs/ops route: `src/**` в diff без code-route Change — отказ.
- Исключения узкие и явные: `.deltafuse/lock.yaml` после installer, `AGENTS.md` product-owned, сами файлы leash-конфига. Не «любой markdown».
- Сообщение: какой путь, почему (нет Change / не тот шаг / не тот route). Без совета «просто выключи leash».

## Не делать

- Автосоздавать Change из diff.
- Блокировать `docs/intake/**` (сырой вход).
- Считать README законом (спека — `docs/spec/**`).

## Acceptance

Продукт с `baseline: accepted`, грязный `src/x.py`, пустой `docs/changes` (кроме README) → `leash` ≠ 0 в `enforce`. Тот же diff при selected implement и пути в `allowed_paths` → 0. Тест на docs-route Change: правка `docs/spec/**` ок, правка `src/**` нет.
