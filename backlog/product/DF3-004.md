# DF3-004 — Core-owned lifecycle transitions

- **Статус:** `blocked`
- **Зависимости:** DF3-002

## Цель

Worker больше не подтверждает собственный прогресс ручным редактированием Change status.

## Работа

1. Ввести отдельный Core command для gate validation + atomic transition.
2. Оставить `next` и `check-gate` read-only.
3. Подключить формальную transition table и удалить дублирующую логику.
4. Записывать transition receipt и проверять соответствие `change.yaml` последнему receipt.
5. Закрывать Analyze только после routing/slices/coverage.
6. При spec rejection возвращать Change в `analyzed`, сохраняя rejected proposal.
7. Перевести `/run` и lifecycle skills на новый command.

## Acceptance

- Jump `normalized -> converged` отклоняется даже при вручную созданных файлах/status.
- Полный Analyze не оставляет пустую очередь в `analyzing`.
- Rejected spec снова выдаёт Specify work.
- Crash между validation и write не оставляет половинчатого transition.
