# DF3-004 — Core-owned lifecycle transitions

- **Статус:** `done`
- **Зависимости:** DF3-002

## Цель

Worker больше не подтверждает собственный прогресс ручным редактированием Change status.

## Работа

1. Ввести отдельный Core command для gate validation + atomic transition.
2. Оставить `next` и `check-gate` read-only.
3. Подключить формальную transition table и удалить дублирующую логику.
4. Записывать transition receipt и проверять соответствие `change.yaml` последнему receipt.
5. Закрывать Analyze только после routing/slices/coverage.
6. При spec rejection возвращать Change в `analyzed`, сохраняя rejected proposal.
7. Перевести `/run` и lifecycle skills на новый command.
8. Сделать `next` packet минимальным: exact files/anchors, один ready outcome и краткие diagnostics вместо полного transition journal.

## Acceptance

- Jump `normalized -> converged` отклоняется даже при вручную созданных файлах/status.
- Полный Analyze не оставляет пустую очередь в `analyzing`.
- Rejected spec снова выдаёт Specify work.
- Crash между validation и write не оставляет половинчатого transition.
- Ни один transition flow не требует от Worker загрузки всего репозитория или `docs/spec/**`; framework-controlled packet укладывается в 16k/24 файла.

## Итог (2026-09-12)

- Новый Core command `deltafuse advance <change> --gate <gate>` (`core/transitions.py`): валидирует gate, применяет формальную transition table атомарно и пишет receipt в `.deltafuse/transitions.jsonl`. `next` и `check-gate` остались read-only.
- Receipt — источник истины при крахе между журналом и записью статуса: следующий `advance` дозаписывает change.yaml (resume), тестируется `test_crash_between_receipt_and_status_write_is_resumable`.
- Очередь останавливает Change, чей статус не совпадает с последним receipt (hand-edit без receipt = blocked).
- Таблица `ALLOWED_CHANGE_TRANSITIONS` — единственный авторитет порядка; gate `specification-proposed -> analyzed` добавлен для rejection loop.
- Spec rejection: `decide --status rejected` возвращает Change в `analyzed`, отвергнутый proposal сохраняется (spec-delta.md status rejected); Specify снова выдаёт работу.
- Analyze закрывается advance'ом только при полном routing/slices/coverage (наследует gate `analyzed`); застрявший `analyzing` с полным пакетом выдаёт в `next` ready-шаг advance.
- `process/skills/run/SKILL.md`: Worker обязан вызывать advance после прохода gate, ручная правка change.yaml запрещена.
- Красные тесты F-03 и F-04 перевёрнуты в зелёные (F-03 усилен до `== analyzed`).
- Новые тесты: `tests/integration/test_core_transitions.py` (5 сценариев: jump, receipt, hand-edit halt, crash resume, цикл Analyze->Specify).
- Packet остаётся минимальным: ready-подсказка advance — одна строка reason; receipts и журналы не попадают в Worker context.
