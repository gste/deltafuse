# DF3-007 — Human Gate receipts и integrity profiles

- **Статус:** `done`
- **Зависимости:** DF3-004

## Цель

Human Gate semantics соответствуют реальной границе доверия и не зависят от редактируемого plaintext journal.

## Работа

1. Развести governance responsibilities, Process stops и Core-recorded clicks.
2. Ввести `local` и `broker-signed` integrity profiles.
3. Определить versioned receipt с artifact digest, verdict, actor/key id, timestamp/nonce и signature.
4. Хранить private key вне Worker filesystem/tool surface; Core проверяет public trust roots.
5. Обнаруживать replay, truncation, replacement и stale-artifact receipts.
6. Обновить halt/host contracts без добавления UI в Core.

## Acceptance

- Редактирование или пересборка journal не создаёт действующий broker-signed Human Gate.
- Local profile явно сообщает более слабую гарантию.
- Merge остаётся host/human gate и не выполняется Core.

## Итог (2026-09-12)

- `core/receipts.py`: versioned receipts (receipt_version 2) с artifact digest, verdict, actor/key id, timestamp/nonce, chain hash и signature.
- Профили integrity (DR-3.0-3): `local` — hash chain только от случайной порчи, честно декларирует слабую гарантию (поле guarantee); `broker-signed` — HMAC-подпись host-брокера ключом из env DELTAFUSE_BROKER_KEY (вне Worker поверхности), верификация по trust roots `.deltafuse/trusted-keys.yaml`; незарегистрированный ключ = отклонение.
- Detect (item 5): редактирование записи (chain mismatch), усечение/замена журнала (head digest), replay nonce; stale-artifact receipt не засчитывается при валидации клика — artifact bytes обязаны совпадать с digest в receipt (fsm `has_valid_receipt`).
- Journal пишется только Core (decide), страница .deltafuse core-owned (gate-journal.jsonl, journal-head, transitions.jsonl, trusted-keys.yaml) выведена из Worker write surface в leash (SEC-03 закрыт, тест перевёрнут).
- Merge остаётся host/human гейтом — CLI не имеет merge-команды (контрактный тест).
- Красный тест SEC-03 перевёрнут в зелёный; остаётся C-01 (DF3-009).
- Новые тесты: tests/unit/test_receipts.py — 8 сценариев (локальная цепочка+декларация, broker round-trip, требование host-ключа, подделка записи, усечение, замена, stale, отсутствие merge CLI).
