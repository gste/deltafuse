# WQ-001 — Очередь работы (без обязательного Change/task в слеш-команде)

- **Дата:** 2026-09-10
- **Статус:** `planned` — концепт; листинг ядра уже в [WK-003](WK-003.md) (`deltafuse next`)
- **Слой:** производная проекция ядра; не второй SSOT. fuse-map читает ту же проекцию, не парсит `docs/changes/**`
- **Зависимости:** [WK-003](WK-003.md). Ортогонально [FM-001](FM-001.md) (колонки доски ≠ «что делать сейчас»)

Сейчас почти каждый вызов `/analyze` / `/declare` требует id Change или task. В 90% случаев это первый готовый артефакт. Человек и fuse-map тоже хотят один список «что сейчас в работе».

## Зачем

- Слеш-команда без аргументов берёт следующий готовый шаг.
- Если брать нечего — ядро говорит почему (DEC, spec gate, пустой репозиторий) и что можно взять (`/intake`, принять DEC, …).
- Человек открывает один текст/JSON, а не бродит по `docs/changes/*/change.yaml`.
- fuse-map получает ready-rail без индекс-файла в продукте (FM-001 это запрещает).

## Контракт (не смешивать SSOT)

| Слой | Роль |
|---|---|
| Product git | Change, TASK, DEC, evidence — единственное хранилище |
| Kernel | считает очередь с диска; `deltafuse next` / `next --list` / `--json` |
| Worker | не выбирает «следующий сам»; спрашивает ядро, если id не дан |
| fuse-map | рисует ready из JSON очереди; колонки Changes — FM-001 `board` |
| Human | смотрит `--list` / `--human` или fuse-map; закрывает DEC/spec/merge |

**Порядок «первый попавшийся»:** `CHG-*` id, затем `TASK-*` номер. Стабильно, без приоритетов в v1.

**Ready** — шаг, который воркер может выполнить (`/analyze` … `/verify`, или `/intake` если активных Changes нет).

**Blocked** — ждать человека: `blocked-on-decision`, `specification-proposed`, task `blocked`. Не подсовывать LLM.

Не писать `queue.yaml` / `docs/todo/**` / индекс «для доски». Проекция эфемерна, как board snapshot.
