# DF3-008 — Schema v3 и Declare contracts

- **Статус:** `done`
- **Зависимости:** DF3-004, DF3-006, DF3-007

## Цель

Устранить legacy `targeting` vocabulary и выпустить согласованные versioned v3 contracts без runtime-совместимости с предыдущими версиями.

## Работа

1. Выпустить schema v3 для Change, task, evidence, receipts, lock и board contracts.
2. Заменить v3 writes `targeting`/`target-confirmed` на Declare-aligned states.
3. Добавить fail-closed диагностику для artifacts неизвестной версии или legacy vocabulary; Core не преобразует их автоматически.
4. Обновить skills, templates, adapters, validators и board layout атомарно.
5. Создавать новые Change artifacts только по schemas v3.

## Acceptance

- В новых v3 product artifacts отсутствуют legacy tokens.
- Artifacts предыдущих версий не читаются как валидные v3 и не изменяются автоматически.
- Неизвестная или частичная версия останавливается с точной диагностикой.

## Итог (2026-09-12)

- Schema v3: change/capability/evidence схемы пинят schema_version 3; canonical templates, builder-фикстуры, CLI validator tests, layout validators и installers (init.sh/init.ps1 SchemaVersion) синхронно на v3.
- Vocabulary: `targeting`->`declaring`, `target-confirmed`->`declared` — 143 токена в 36 файлах (core, queue, transitions, board, bench, skills, templates, tests) атомарно; bundle перегенерирован.
- Fail-closed (item 3): `validate_change_package` отклоняет change.yaml с schema_version != 3 («migrate manually — no automatic conversion») и legacy-лексику v2 в change.yaml/slices/tasks; unknown/partial версии останавливают с точной диагностикой; артефакт не модифицируется.
- scaffold пишет schema_version: 3; новые артефакты создаются только по v3 (item 5).
- Тесты: tests/unit/test_contract_v3.py (4 сценария: scaffold v3, unknown version, legacy vocabulary, gate order).
