## Changes and scope

The public baseline is now provable end to end. `public_suite/` holds a
standard-library-only HTTP client (deadline-based convergence polling of the
canonical flow observation: `caught_up=true` with every component sequence at
`required_sequence`) and a Kafka observation client that consumes the
run-owned topics from inside the private network through the digest-pinned
tools image — no broker port is ever exposed. `baseline_suite.py` runs the
deterministic scenarios of `seed/tests/system/fixtures` with stable named
assertions `J03-PUB-001…012` and the published exit contract (0 pass, 1
valid failure, 2 invocation, 3 infrastructure): approve flow, reject flow,
immutable-version guard, idempotent replay guard (prior outcome, unchanged
audit, exactly one decision event on the topic), decision conflict, and
Kafka event observability. `tests/bench/document_flow/test_public_baseline.py`
validates the suite sources, fixtures, assertion names and exit contract
portably, executes a duplicate-audit counterexample against the named
replay-guard assertion without a stack, and runs the live suite when
`J03_PUBLIC_BASELINE_LIVE=1` selects it.

Recorded scope adjustments (both completing invariants of earlier cards that
module-scoped tests could not observe):

1. The J03-207 canonical query shipped only stub projection clients
   (`available=false`, sequence 0), so the flow watermark could never
   converge. Added the workflow-service read endpoint
   `GET /api/workflows/documents/{documentId}/projection` (read-only route
   state, open slots and workflow aggregate watermark) and real HTTP
   projection clients in document-service
   (`HttpWorkflowProjectionClient`, `HttpAuditProjectionClient`) registered
   by `FlowQueryConfiguration` behind `j03.query.*-base-url` properties;
   compose supplies the service-to-service URLs. Without a configured URL
   the previous stub remains, so existing module tests are unaffected.
2. The J03-205 decision flow violated DEC-D: repeating a `decision_id`
   with the same canonical payload under a new operation returned
   `IDEMPOTENCY_CONFLICT` because the receipt comparison embedded the
   original operation and event identities. `WorkflowCommandService`
   now compares only the decision binding for decision-level replay and
   returns the prior result (no domain, audit or outbox effect); a changed
   binding still conflicts.
