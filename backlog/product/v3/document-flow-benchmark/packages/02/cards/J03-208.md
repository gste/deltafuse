## Changes and scope

One documented command (`infra/stack.ps1 -Action up -RunId <id>
-MavenRepository <sealed-cache>`) now starts the complete baseline:
offline Maven `package dependency:copy-dependencies`, Compose model
validation, digest-resolved image build, fresh run-owned volumes, and
`up --wait` against a 180-second default health deadline, finishing with a
label ownership assertion and status output. The compose model pins image
digests, keeps PostgreSQL/Kafka on an internal network with no host ports,
publishes only the three service HTTP ports on 127.0.0.1, gives every
service read-only root filesystems with a bounded tmpfs, `cap_drop: ALL`,
`no-new-privileges`, CPU/memory/pids limits, run-owned labels, and no
Docker socket or host checkout mounts. Database principals stay separated
exactly as provisioned by J03-203; the entrypoint script
`infra/postgres/init/02-runtime-credentials.sh` injects per-run LOGIN
passwords from launcher-generated secrets (never committed) and applies the
judge default-privilege grants per database. `infra/fault.ps1` provides
externally controlled, label-verified stop/recover of any of the five named
services with a bounded recovery poll; `stack.ps1 -Action status/preserve/
down` covers inspection, evidence preservation, and ownership-checked
teardown (exact project, its networks and volume only; no global pruning).

Recorded scope adjustments:

1. Service sources (J03-204/J03-205 outputs): `DocumentCommandService` and
   `WorkflowCommandService` each declared a public single-argument
   constructor plus a package-private test-hook constructor without any
   `@Autowired` annotation, so the composed container failed Spring
   instantiation (`No default constructor found`; document-service
   `exited (1)` in the first full-boot attempt). Module-scoped tests never
   loaded the full context, so the defect first surfaced on the real stack.
   Fix: `@Autowired` on the intended public constructor of each class.
2. Compose networking: with the app services attached only to the internal
   network, Docker silently ignored the 127.0.0.1 port publications (port
   publishing is unsupported on internal networks), so the documented
   loopback HTTP exposure was inert. Fix: services now attach to a second,
   non-internal `j03_frontend` network that carries only the published
   ports; PostgreSQL and Kafka remain on the internal network only.

Launcher defects found and fixed during the first live startups (all inside
this card's write set): the run-state directory collided with the checkout
because the worktree itself lives under `%TEMP%\deltafuse-j03`, which put
per-run secrets inside the repository (`j03208green2/state.json`); the state
root now uses `%LOCALAPPDATA%\j03-run-state`. Windows PowerShell 5.1 strips
embedded double quotes from native `--format` arguments, so the ownership
label lookup now uses `--format json | ConvertFrom-Json`. State and evidence
writes use an explicit BOM-less UTF-8 encoder instead of the PS-5.1-
incompatible `-Encoding utf8NoBOM`. Fault recovery looks up stopped
containers with `compose ps -qa` (plain `-q` cannot see a stopped service).
The earlier unquoted-tmpfs YAML bug from the first startup attempt
(candidate-tmpfs.log: daemon rejected `mode=1777` as a mount path) was
already fixed by quoting the tmpfs entry.
