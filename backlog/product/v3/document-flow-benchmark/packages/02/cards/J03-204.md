## Changes and scope

`DocumentCommandService` implements create-document, create-version, and
submit-version on one JDBC transaction per command. Each transaction stores
domain state, a typed baseline outbox payload, and a stable command receipt.
The receipt binds the public operation ID to a canonical parsed-field payload;
an exact replay returns the stored result while a changed payload fails with
`IDEMPOTENCY_CONFLICT`. Document-row locking serializes per-document sequence
allocation. Submission changes only the addressed draft to `SUBMITTED`; a
second operation receives `VERSION_IMMUTABLE`.

Forward-only V2 adds receipts and enforces at most one current draft version per
document. The J03-203 V1 migration was not edited. A before-commit test hook
injects failure after every intended write and proves database rollback; it is
not an application endpoint. `DocumentController` exposes only the three
published baseline mutations, explicit identity binding, snake-case JSON, and
closed public error codes. No route or target multi-stage behavior is present.
