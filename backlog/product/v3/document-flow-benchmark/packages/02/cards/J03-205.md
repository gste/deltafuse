## Changes and scope

`WorkflowCommandService` consumes a validated baseline version-submitted event
to create exactly one pending route with one assigned approver. One local
transaction records the input event, route, canonical replay receipt, and
route-created outbox payload. Exact duplicate delivery returns the stored
result; changed content under the same event ID fails. A PostgreSQL transaction
advisory lock keyed by document plus a partial unique index serialize competing
submissions and allow only one pending baseline route per document.

A decision locks its route, checks document/version/route/actor identity before
state rules, derives APPROVED/REJECTED from the closed action, and atomically
writes the decision, closed route state, canonical receipt, and decision-applied
outbox payload. `(route_id, decision_id)` is the domain idempotency key. The
HTTP adapter parses through the closed canonical JSON contract and rejects
unknown members or path identity mismatches before calling the service.

Forward-only V2 adds route/decision receipts and the pending-route uniqueness
guard. J03-203's V1 migration was not edited. The only vocabulary remains
`approver`, `APPROVE|REJECT`, and `PENDING|APPROVED|REJECTED`; registrar,
experts, escalation, late decisions, and supersede are absent.
