## Changes and scope

The private `version-supersede` overlay applies only to a fresh public-seed
copy. A per-document database lock serializes route creation; a new version
atomically changes the prior pending route to `SUPERSEDED`, emits its ordered
route event, and inserts the successor route and receipt in the same JDBC
transaction. A forced before-commit failure rolls all of those effects back.
Decisions arriving for a superseded route do not insert or mutate a decision;
they create one idempotent `IGNORED_LATE_DECISION` receipt/event, and replay is
silent. Route/document/version identity remains enforced.

The overlay contains its own Flyway migration, reference service, live harness,
and the baseline concurrency test adapted to the supersede contract. The public
seed is byte-unchanged and contains none of the private target semantics. The
independent interpreter from J03-302 was restored unchanged after the interrupted
session briefly added baseline-role compatibility outside this card's write set.
