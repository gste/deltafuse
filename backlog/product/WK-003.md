# WK-003 — Контракт шага + `deltafuse next`

- **Дата:** 2026-09-10
- **Статус:** `done` — `deltafuse next` на `feature/2026-09-10-worker-kernel`
- **Слой:** CLI + Python API (`STEP_CONTRACTS`, очередь ready/blocked)
- **Зависимости:** [WK-001](WK-001.md). Очередь как продукт — [WQ-001](WQ-001.md). Не зависит от FM-001

Ядро отвечает на «какой шаг сейчас», без LLM и без обязательного id Change.

## Зачем

Скилл знает reads/writes/gate только текстом. Оркестратор и человек не могут спросить машину «что дальше». Слеш-команда без id должна взять первый ready элемент очереди (WQ-001).

## Минимум

Машинный контракт семи шагов: skill, gate, ключ `PHASE_CONTRACTS`.

```text
deltafuse next [path] [--list] [--json] [--step analyze|specify|decompose|declare|implement|verify|intake]
```

- `path` опущен или корень продукта — очередь всех активных Changes
- `path` на пакет Change — только он
- без `--list` — один выбранный ready (первый по id)
- `--list` — все ready, затем blocked
- `--step` — фильтр; нет такого ready → exit 1 и подсказка
- пустая очередь: exit 1; если Changes нет — ready `/intake`; если всё blocked — причина и «новый Change: /intake»
- не вызывает LLM, не пишет файлы, не гоняет `check-gate` на каждый CHG

Skills: если Change/task не назвали, выполнить `deltafuse next --step <этот>` и взять `path` / `task_path`.

## Не делать

- HTTP, MCP, auto-accept DEC
- индекс-файл очереди в продукте
- fuse-map UI (WQ-001 / FM-001)
- второй процесс для людей (WK-004)

## Acceptance

- Два Changes: выбран меньший `CHG-*`
- Decomposed + `TASK-001` pending → `/declare` и путь задачи
- Нет Changes → `/intake`
- `blocked-on-decision` без другого ready → exit 1, в выводе DEC/status
- `--json` на stdout; дерево продукта не меняется
