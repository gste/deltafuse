Воркер пишет тесты и код. Ядро **само** гоняет команду и пишет `evidence/red|green|regression`. Иначе Red/Green — то, что модель согласилась записать (A09 F-009).

## Зачем

Гейт `targeting` уже отвергает `_` и принимает `already-green`, но YAML с `exit_code` / `failure_category` пишет исполнитель. ImportError можно выдать за `behavioral-mismatch`. TEST-004 требует, чтобы категорию ставил прогон, не промпт.

## Минимум в DeltaFuse (эта карточка)

```text
deltafuse evidence <change-dir> --phase red|green|regression --task TASK-NNN \
  --changed-path <rel> [--timeout 90] -- <argv>
```

Поведение:

- cwd = корень продукта; `argv` без `shell=True`
- пишет `evidence/<phase>/<task>.yaml` (`schema_version: 2`); `changed_paths` — из `--changed-path` (posix)
- **red, exit 0** → `already-green`
- **red, exit ≠ 0** → классификация лога: `syntax-error` / `import-error` / `behavioral-mismatch` / `fixture-error`
- authentic Red (CLI 0) только `expected-failure` + `behavioral-mismatch` (route `code`) и без `_` в тестах из `changed_paths`; иначе YAML всё равно пишется, CLI 1
- **green/regression, exit 0** → `passed` + `base_revision`; иначе `failed`, CLI 1
- не вызывает LLM, не трогает `change.yaml` / status задачи, не auto-accept DEC

Гейт `targeting` (route `code`): `expected-failure` без `behavioral-mismatch` — ошибка.

Скиллы Declare/Implement: не заполнять evidence YAML вручную; вызвать эту команду.
