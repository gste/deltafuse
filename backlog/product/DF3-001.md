# DF3-001 — V3 contracts и adversarial baseline

- **Статус:** `ready`
- **Зависимости:** нет

## Цель

До исправлений превратить принятые findings в воспроизводимые тесты, закрепить границы доверия и доказать исходную точку качества на 35B A3B при окне 32k.

## Работа

1. Добавить v3 decision records для transition authority, distribution и integrity profiles.
2. Описать v2 -> v3 compatibility matrix: config, lock, Change, evidence, journals, adapters.
3. Добавить падающие тесты для F-01, F-02, SEC-01, SEC-02, F-03/F-04, B-01, B-04, SEC-03/04 и C-01.
4. Разделить тесты на accidental misuse и adversarial Worker.
5. Зафиксировать, какие проверки принадлежат Core, host и CI.
6. Добавить в канон Small-LLM Quality Contract: одна capability, один artifact layer и один outcome на Worker-вызов.
7. Зафиксировать 32k как полный qualification window, 16k/24 файла как default framework-controlled input budget и обязательный запас для host/tool/output.
8. Выполнить минимум три чистых v2-прогона M01 и M02 на `ornith-1.5-35b-a3b` через LM Studio без подмены cloud/mock моделью.
9. Сохранить framework/model manifest, per-run disk score, stages/retries, фактический context peak, число файлов, hallucinated paths и envelope violations.
10. До implementation-коммитов установить численные v3 release thresholds на основе baseline; последующее ослабление требует maintainer Decision.

## Acceptance

- Каждая принятая P0/P1 гипотеза имеет минимальный воспроизводящий тест или явно записанную причину переноса теста в зависимую карточку.
- Contracts не обещают защиту от полностью скомпрометированной OS.
- Никакая реализация не меняется в этой карточке.
- Целевая нижняя граница явно записана как 35B A3B / 32k, а более крупная или cloud LLM не является скрытой зависимостью.
- Baseline состоит минимум из трёх независимых чистых прогонов на case; агрегируется медианой, отдельные результаты не перезаписываются.
- Для M01/M02 определены численные correctness/process/context thresholds, которые использует DF3-009.
