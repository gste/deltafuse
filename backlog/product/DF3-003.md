# DF3-003 — CI leash и framework manifest

- **Статус:** `done`
- **Зависимости:** DF3-001

## Цель

Сделать pin и CI leash проверкой фактически исполняемого кода и реального commit range.

## Работа

1. Добавить leash input `--base`/`--head` с точными SHA и отдельной проверкой dirty/untracked paths.
2. Для GitHub PR использовать base/head SHA, для push — before/after; обеспечить нужную fetch depth.
3. Включить `src/deltafuse/**`, entrypoints и runtime assets в versioned framework manifest.
4. Синхронизировать Python, PowerShell и Bash hash implementations.
5. Проверить tampering, rename, delete, submodule и shallow checkout cases.

## Acceptance

- Чистый PR checkout с out-of-envelope commit падает в CI.
- Любое изменение Core меняет content hash.
- Один canonical manifest даёт одинаковый digest на Windows и POSIX.

## Итог (2026-09-12)

- `leash` CLI: `--base`/`--head` — диф точного commit range вместо пустого worktree (SEC-01); `git_dirty_paths(root, base=, head=)`; untracked остаются отдельной всегда включённой проверкой; `--head` без `--base` — ошибка.
- Шаблон `deltafuse-leash.yml`: `fetch-depth: 0`; PR — `pull_request.base.sha/head.sha`, push — `before/after`; zero-SHA base и недоступный base деградируют в локальную проверку с `git fetch` подстраховкой.
- Framework manifest: `src/deltafuse/**` и `pyproject.toml` (entrypoints) включены в content hash (SEC-02); `hasher.py`, `scripts/init.sh` и `scripts/init.ps1` синхронизированы (один canonical manifest, POSIX-нормализация путей).
- Красные тесты SEC-02 перевёрнуты в зелёные; SEC-01 теперь покрыт тестом `test_clean_checkout_with_out_of_envelope_commit_fails_ci`.
- Новые тесты: tamper/delete/rename/entrypoint меняют hash; детерминизм digest; base/head range ловит out-of-envelope commit на чистом checkout; untracked проверяются вместе с range; `--head` без `--base` отклоняется.
