# WK-001 — Ядро процесса отдельно от бэка исполнителя

- **Дата:** 2026-09-10
- **Статус:** `planned` — контракт на `feature/2026-09-10-worker-kernel`
- **Слой:** продуктовый контракт в этом репозитории; реализация WK-002…WK-005 на этой же ветке, пока не сказано иначе
- **Зависимости:** нет кода FM-001. Ортогонально: доска читает ядро, не воркера

Эта карточка фиксирует split. Канонические `docs/**` и `process/skills/**` не трогать, пока контракт не принят.

## Зачем

Сейчас skill = контракт шага + промпт исполнителя в одном файле. Гейты, evidence и «какой шаг следующий» живут рядом с текстом для LLM. Из-за этого:

- человек не может пройти тот же Change без второго процесса «для людей»;
- скрипт/оркестратор не может вызвать шаг, не подсовывая модель;
- качество Red/Green зависит от того, вспомнит ли воркер прогнать команду (A09 F-009).

Разделить: **ядро процесса** владеет гейтами, evidence и оркестрацией по диску; **бэк исполнителя** только пишет артефакты. I/O одно и то же для `llm | human | script`.

## Три слоя (не смешивать)

| Слой | Где живёт | Что делает | Чего не делает |
|---|---|---|---|
| **Kernel** | этот репозиторий: схемы, FSM, CLI, lock/hash, будущий evidence runner и `next` | читает git продукта; `check-gate` / `evidence_run` / `next_step`; halt, если гейт не прошёл | не пишет claims, spec prose, TASK, тесты, код продукта; не вызывает модель |
| **Worker** | адаптер `llm \| human \| script` | пишет только артефакты Change (routing, spec, TASK, evidence YAML, код/тесты в рамках шага) | не решает гейт; не классифицирует Red/Green; не выбирает «следующий шаг» сам |
| **Human Gates** | DEC / accept spec / merge | человек принимает решения и merge | не воркер и не LLM; не дублирует lifecycle |

Продуктовый git — единственное хранилище. Воркер пишет файлы; ядро проверяет их; человек закрывает DEC/spec/merge.

```text
Worker  --artifacts only-->  Product git
Kernel  --check_gate / evidence_run / next_step-->  Product git
Human   --DEC / spec / merge-->  Product git
Kernel  --halt if gate fail-->  Worker
```

- `process/skills/*/SKILL.md` — один из адаптеров (`llm`), не источник истины для гейта.

Исполнитель-человек заполняет **те же** файлы Change (`docs/changes/<id>/**`, evidence). Второго lifecycle нет.

## I/O воркера

Воркер на любом бэке:

- **читает** то, что разрешает контракт шага (и `PHASE_CONTRACTS`);
- **пишет** только артефакты шага в product git;
- **не запускает** гейт и не интерпретирует exit code как статус Change — это ядро;
- после записи ядро делает `check-gate` (и позже `evidence_run`). Halt → воркер останавливается, файлы остаются на диске.

Одинаковый контракт для LLM, человека и скрипта. Разница только в том, кто заполняет файлы.
