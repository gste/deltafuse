# F-005: Отсутствие поддержки статусов cancelled и superseded для задач на гейте converged

- **Дата обнаружения:** 2026-09-06
- **Обнаружено в задаче:** [A05-01](../analysis/packets/A05-01.md)
- **Затрагиваемые компоненты:** `src/deltafuse/core/fsm.py` (`check_gate :: converged`, строка 447), `process/schemas/task.schema.yaml`
- **Затрагиваемые критерии:** `PROC-002` (FSM Determinism), `PROC-003` (Crash Resilience & Re-entrance), `TEST-004` (TDD Red Authenticity)
- **Статус:** `mitigated` (RM-005, 2026-09-09)

## Описание дефекта

В схеме `process/schemas/task.schema.yaml` для статуса задачи задекларированы терминальные состояния отмены и замены:
```yaml
status: {enum: [pending, targeting, target-confirmed, implementing, implemented, verified, blocked, cancelled, superseded]}
```

Однако в `src/deltafuse/core/fsm.py` при проверке гейта схождения пакета изменений (`check_gate(..., "converged")`) проверка терминальности задач жестко захардкожена:
```python
task_status = meta.get("status")
if task_status not in {"implemented", "verified"}:
    errors.append(
        f"Gate converged: task '{task_file.name}' has non-terminal status '{task_status}' "
        "(must be 'implemented' or 'verified')"
    )
```

### Последствия дефекта
1. **Невозможность безопасной отмены/замены задач при повторной декомпозиции**:
   - Если в процессе реализации срез был пересмотрен, и ранее созданная задача `TASK-001` была отменена (`status: cancelled`) или заменена более точной задачей `TASK-002` (`status: superseded`), пакет изменений **никогда не сможет пройти гейт `converged`**.
   - FSM выдаёт ошибку: `task 'TASK-001.md' has non-terminal status 'cancelled' (must be 'implemented' or 'verified')`.
2. **Вынужденное нарушение чистоты аудита**:
   - Чтобы обойти этот отказ, инженеру или агенту приходится либо удалять файл задачи с диска (теряя исторический provenance и отменяя аудит отклонённых шагов), либо фиктивно проставлять `status: implemented / verified` без наличия фактической реализации и тестов.

## Достижимость Red для зависимых задач (Change-level vs Task-level Red)
В эксперименте A05-01 также исследована семантика Red-свидетельства для зависимых задач в цепочке `TASK-001 -> TASK-002`:
- Для `TASK-002` (зависящей от `TASK-001`) падающий тест может не компилироваться или падать с инфраструктурной ошибкой (`ImportError`, отсутствие класса/таблицы из `TASK-001`) до реализации `TASK-001`, что формально нарушает критерий `TEST-004` (Red-тест должен падать по семантическому несовпадению `behavioral-mismatch`, а не из-за синтаксиса или инфраструктуры).
- Решение: FSM требует топологического порядка исполнения DAG — `TASK-002` переходит в Declare строго после того, как `TASK-001` достиг состояния `implemented`.

## Рекомендации по устранению

1. В `src/deltafuse/core/fsm.py` расширить набор допустимых терминальных статусов на гейте `converged`:
   ```python
   if task_status not in {"implemented", "verified", "cancelled", "superseded"}:
   ```
2. Добавить проверку в `coverage.yaml`: если задача помечена как `cancelled` или `superseded`, покрываемые ею `CR-*` должны быть либо переназначены на активные задачи, либо иметь статус `rejected`/`superseded`.

## Статус исправления

**Исправлено (RM-005, 2026-09-09):** `check_gate(..., "converged")` принимает task status ∈ {implemented, verified, cancelled, superseded}. `pending` по-прежнему fail. Переназначение claims в `coverage.yaml` (рекомендация 2) не входило в минимум.
