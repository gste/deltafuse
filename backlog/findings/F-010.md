# F-010: Гейт `specified` принимает пакет без живой спецификации

- **Дата обнаружения:** 2026-09-07
- **Обнаружено в задаче:** [A09-02](../analysis/packets/A09-02.md) (holdout S01 r2)
- **Затрагиваемые компоненты:** `src/deltafuse/core/fsm.py` (`check_gate` / `specified`), `process/skills/specify-change/SKILL.md`
- **Затрагиваемые критерии:** `SPEC-001` (intent в нормативной spec), `SPEC-004` (достаточность spec)
- **Тип:** `defect` (слабый gate)
- **Статус:** `confirmed` на S01 r2-frozen. Skills **не** патчить в A09.

## Ожидаемое

Гейт `specified` подтверждает, что нормативное поведение попало в `docs/spec/**` (или доказано `requirement_delta: none` точными `spec_refs`). Для bootstrap (пустой каталог) обязателен живой spec-файл capability и согласованный `_capabilities.yaml`.

## Наблюдаемое

`check_gate(..., "specified")` проверяет только существование `spec-delta.md` и отсутствие unresolved Decisions. На S01 r2 харнесс получил `gate ok` при:

- шаблонном `docs/spec/context.md` без контракта limiter;
- отсутствии `docs/spec/security/ratelimit.md`;
- `_capabilities.yaml` с выдуманной формой (`requirements: [CR-001, …]`, не `spec`/`code_roots`);
- `change.yaml` всё ещё `status: normalized`.

Независимый oracle S01 (`acceptance_criteria.spec_files`) не выполнен. Hidden suite не к чему применять: кода нет.

## Влияние

Калибровка S02/S03 маскировала дыру харнесс-подсказками («пиши `docs/spec/security/ratelimit.md`»). Holdout без этих extras проходит FSM Specify вхолостую. Дальнейший Decompose падает на схеме `change.yaml` (slices как строка, tasks как объекты).

## Минимальный вариант исправления

Гейт `specified`: live spec paths из spec-delta ADDED/MODIFIED существуют; catalog schema валиден; `change.yaml` status ∈ {specified, specification-proposed}. Не полагаться на существование одного `spec-delta.md`.

Отложить в A12. Не чинить по результатам holdout промптами.
