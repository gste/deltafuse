## Описание дефекта

В `src/deltafuse/core/context.py` функция `estimate_tokens(text)` реализована через наивную эвристику подсчёта слов:
```python
def estimate_tokens(text: str) -> int:
    """Estimates token count using the standard word heuristic (1 word ≈ 1.3 tokens)."""
    words = text.split()
    return math.ceil(len(words) * 1.3)
```

В задаче **A03-01** было проведено сравнительное измерение оценки `estimate_tokens` против фактического BPE-токенизатора рабочей локальной модели `ornith-1.5-35b-a3b` (архитектура `qwen35moe`) на типовых артефактах фреймворка DeltaFuse.

### Результаты измерений

| Тип данных | Число слов (`split()`) | Оценка DeltaFuse (`words * 1.3`) | Реальные токены (Ornith / Qwen3.5) | Ошибка оценки |
|---|---|---|---|---|
| **Английская проза (EN)** | 20 | 26 | 26 | **0.0%** (идеально) |
| **Русский текст (RU)** | 17 | 23 | 37 | **-37.8%** (занижение в 1.6x) |
| **Python-код** | 30 | 39 | 81 | **-51.9%** (занижение в 2.1x) |
| **YAML-манифест / спецификация** | 22 | 29 | 98 | **-70.4%** (занижение в 3.4x) |
| **Трассировочные логи / метки времени** | 35 | 46 | 168 | **-72.6%** (занижение в 3.7x) |

## Архитектурные последствия

1. **Ложное ощущение соблюдения лимитов (False Security)**:
   - При установленном лимите `max_tokens: 16000`, агент может загрузить пакет из YAML-схем, логов и кода, который по расчёту `estimate_files_tokens` составляет ~15,000 токенов (валидация `validate_context_budget` проходит успешно).
   - Однако фактический объём токенов в промпте превысит 45,000–55,000 токенов.
   - Это превышает физический размер загруженного контекста модели (33,024 токенов), что неминуемо приводит к отсечению контекста (truncation), потере системных инструкций, галлюцинациям либо аварийному падению сервера инференса (OOM / context overflow).
2. **Неучёт структурных элементов промпта**:
   - `estimate_files_tokens` считает только сырое содержимое переданных файлов.
   - Он полностью игнорирует системный промпт роли, текст навыка (skill instructions), заголовки сообщений Jinja/ChatML, описание доступных MCP-инструментов и обязательный резерв токенов на генерацию ответа и reasoning-фазу (в [A03-03](../analysis/experiments/A03-03/profile.md) reasoning занял 46 токенов на простейшем пинге).

## Рекомендации по устранению

1. **Для быстрого исправления**: Ввести дифференцированные коэффициенты по расширению файлов (`.py`: 2.7, `.yaml`/`.yml`: 4.0, `.log`: 4.5, не-ASCII/кириллица: 2.2).
2. **Для архитектурного решения**: Добавить в CLI / `context.py` поддержку точного токенизатора через локальный эндпоинт токенизации модели (`/tokenize`) или быстрый офлайн-токенизатор (`tiktoken` / `tokenizers` / HuggingFace Fast Tokenizer) с явным учётом оверхеда ChatML-шаблона и резерва ответа.

## Статус исправления
