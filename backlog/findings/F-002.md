# F-002: Отсутствие runtime enforcement для ограничений чтения и пропуск проверки бюджетов контекста для фаз Target и Implement

- **ID:** F-002
- **Тип:** limitation
- **Затронутый критерий:** `PROC-004` (Bounded Execution & Context), `SPEC-005` (Navigability & Context), `CODE-002` (Scope & Boundary Isolation)
- **Ревизия обнаружения:** `60ea40438b0142797848356c660ab88286565e7d` (HEAD: `d4c0d7b37a4e69b3506114eb9a68eebfa838e55e`)
- **Точные ссылки:**
  - `src/deltafuse/core/context.py:14-103` (константа `PHASE_CONTRACTS`)
  - `src/deltafuse/core/fsm.py:209-218` (валидация `context_budget` только для `slices/`)
  - `src/deltafuse/core/fsm.py:223-263` (отсутствие валидации бюджетов в блоке `tasks/`)
  - `process/schemas/task.schema.yaml:1-29` (отсутствие поля `context_budget`)
  - `docs/context-model.md:140-157` (декларация бюджетов и запретных зон чтения)

## Ожидаемое и наблюдаемое

- **Ожидаемое:** Согласно `docs/context-model.md` и `docs/roles.md`, каждая фаза жизненного цикла выполняется под строгим контролем контекстного контракта: агент ограничен по чтению (`Allowed Read Scope`, `Forbidden Read Scope`), а каждая задача выполняется в пределах жесткого бюджета (`max_tokens: 16000`, `max_files: 24`). При выходе за бюджет или попытке чтения запрещённых областей гейт жизненного цикла должен блокировать переход.
- **Наблюдаемое:**
  1. Структура `PHASE_CONTRACTS` в `src/deltafuse/core/context.py` объявляет `allowed_read` и `allowed_write` для всех 7 фаз, но **никогда не используется** в `fsm.py` или CLI для проверки прав доступа. Контроль чтений остаётся сугубо декларативным (текстовая инструкция в prompt агента).
  2. В `process/schemas/task.schema.yaml` поле `context_budget` не предусмотрено схемой.
  3. В `src/deltafuse/core/fsm.py` вызов `validate_context_budget` происходит только для файлов в `slices/` (строка 217). В фазах Target и Implement, где риски переполнения контекста максимальны из-за исходного кода и тестов, проверка бюджета токенов/файлов полностью отсутствует.
  4. Проверка `validate_context_budget` оценивает размер исключительно файлов из `spec_refs`, полностью игнорируя размер промпта навыка (`SKILL.md`), системный промпт, тело самого документа задачи/слайса и историю диалога.

## Минимальное воспроизведение

1. Создать задачу `docs/changes/CHG-001/tasks/TASK-001.md`, которая содержит 50 файлов в `spec_refs` или `allowed_paths`, суммарный размер которых превышает 100 000 токенов.
2. Запустить `deltafuse validate docs/changes/CHG-001` или `deltafuse check-gate docs/changes/CHG-001 --gate decomposed`.
3. Валидация завершится успешно (exit code 0), так как FSM не проверяет бюджеты задач.
4. Проверить код `src/deltafuse/core/fsm.py`: константа `PHASE_CONTRACTS` не импортируется и не упоминается в логике гейтов.

## Влияние

- Локальные LLM с контекстным окном 16k-32k токенов (например, `ornith-1.5-35b-a3b`) на фазах Target и Implement могут молча получать промпты, превышающие их физическое окно контекста, что приведёт к обрезке контекста средой исполнения, потере фокуса внимания и галлюцинациям.
- Агент может нарушать запреты на чтение (например, подглядывать в реализацию при написании Red-теста в Target), и FSM не зафиксирует это нарушение post-factum.

## Уверенность

Абсолютная (100%). Подтверждено статическим анализом исходных кодов `context.py`, `fsm.py`, `cli.py` и схемы `task.schema.yaml`.

## Варианты исправления

1. **Рекомендуемый:**
   - Добавить опциональное поле `context_budget` в `task.schema.yaml` (аналогично `slice.schema.yaml`);
   - В `fsm.py` в блоке валидации `tasks/` вызывать `validate_context_budget` для каждой задачи по файлам из `spec_refs` + `allowed_paths`;
   - В `deltafuse lint-context` поддержать валидацию задач (`tasks/`);
   - В документации явно зафиксировать архитектурное различие: запрет чтения (`forbidden_paths`) обеспечивается средой исполнения агента (IDE/CLI agent tools allowlist), а FSM обеспечивает структурную проверку заявленных ссылок и бюджетов.
2. **Минимальный:**
   - Документировать в `docs/context-model.md`, что `PHASE_CONTRACTS` — это спецификация для настройки контекстных фильтров агентных сред, а не runtime-перехватчик Python-пакета.

## Стоимость контекста и сопровождения

Низкая. Добавление проверки бюджета задач требует ~15 строк кода в `fsm.py` и обновления `task.schema.yaml`.
