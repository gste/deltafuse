# F-008: Гейт analyzed не узнаёт claims вида O1/E1 — только CR-*

- **Дата обнаружения:** 2026-09-06
- **Обнаружено в задаче:** [A09-01a](../analysis/packets/A09-01a.md)
- **Затрагиваемые компоненты:** `src/deltafuse/core/integrity.py` (`extract_claims_from_request`), `process/skills/intake/SKILL.md`, `process/schemas/slice.schema.yaml`, гейт `analyzed`
- **Затрагиваемые критерии:** `SPEC-001` (сохранение claims), `PROC-001` (provenance / неизменность request)
- **Тип:** `defect` (ловушка процесса после Intake)
- **Статус:** `mitigated` (RM-018, 2026-09-09). Skills Intake уточнены после гейта; `request.md` не переписывается.

## Ожидаемое

Intake skill: стабильные `CR-*` claims, плюс ярлыки observation/expectation/constraint/hypothesis. Analyze покрывает те же ID. `check_gate(..., analyzed)` проходит, если coverage отражает claims из `request.md`.

## Наблюдаемое

S02 r2-frozen: ornith в `request.md` дал ID `O1`…`U3` (ярлык стал идентификатором). `check_gate(intake)` это принял.

`extract_claims_from_request` ищет только `\b(CR-[0-9]{3,})\b` → из этого `request.md` список **пустой**.

Coverage честно смапил `O1`…`U3` на `SLICE-01`. Схема `coverage.yaml` валидна. `validate_change_package` / `analyzed`: все 12 ключей — orphans «not found in request.md», хотя они там есть как заголовки.

Слайс при этом требует `claims: [CR-001, …]`. Три алфавита ID на одном Change.

Правка `request.md` после Intake запрещена skill'ом. Без патча экстрактора или повторного Intake гейт `analyzed` на этом пакете не зелёный.

## Минимальное воспроизведение

Продукт `backlog/analysis/experiments/A09-01/work/S02-r2/`, пакет `CHG-001-ratelimit-cooldown`. `python -c` `extract_claims_from_request` → `[]`; `check_gate(..., "analyzed")` → 12 orphan errors. Логи: `experiments/A09-01/runs/S02/r2-frozen/analyze-coverage/`.

## Влияние

Ошибка формы ID на Intake необратимо блокирует Analyze. Пустой coverage (ноль CR-*) напротив прошёл бы completeness — ложный pass.

## Уверенность

Высокая на этом пакете. Пока один repeat; не менять фреймворк, пока не будет 3× / S03.

## Вариант исправления (A12, не сейчас)

1. Экстрактор: те же ID, что intake реально пишет, или жёсткий fail Intake если нет `CR-*`.
2. Skill Intake: одна строка «id = CR-NNN, тип = observation|…, не O1».
3. Проще: гейт Intake не pass без хотя бы одного `CR-*`.

Не ослаблять holdout, подгоняя skill под S02 в середине A09.

## Статус исправления

**Исправлено (RM-018, 2026-09-09):** `extract_claims_from_request` находит `CR-*` и bullet-ID вида `O1`/`E1`/`U3`. Slice `claims` принимает те же стабильные ID. Coverage по-прежнему требует полный mapping; extra поля routing не добавлялись.
